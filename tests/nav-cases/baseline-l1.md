## 结论与读法

200 例：通过 **32**、失败 168、过期 0，准确率 **16.0%**。**类型引用（#37 验收口径）20/20。**

**这个数字低是预期之中的，不是缺陷。** 这 200 个用例是按「**按名称解析一定会错**」的标准人工挑的
（见 `README.md` 的分类表：`var` 推断、重载、扩展方法、经接口调用……每一类都要求同名符号在项目中不唯一）。
L1 是只看声明、不做类型推断的快速索引，在这种点上本来就只能给同名候选。它的用途是
**索引构建期间先给出结果**（`UX_SPEC` §2.2：标为「近似」，就绪后静默变精确），不是替代 L2。

因此这张表的正确读法是：

- `type_ref`（类型引用）20/20 —— L1 自己的验收口径（#37），满分；
- `partial`（medium 33.3% / large 66.7%）、`generic`（large 42.9%）—— 写出类型名时 L1 能解析；
- 其余各类接近 0 —— **预期**，这些点上 L1 只能给同名候选，界面会标成「近似」。

把这张表当成「索引构建期间体验如何」的基线：用户在这段时间里按 `F12` **总能立即得到结果**，
其中类型名一定对，成员名可能跳到同名的另一个符号，界面始终标明是近似结果。
