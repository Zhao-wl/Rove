# 上下文篮子：各 AI 工具的引用格式（阶段 0.3d）

> 版本：v0.1（调研结论 + 待实测） · 日期：2026-11-09
> 对应：UX_SPEC §5.3“复制为引用”

## 1. 调研结论

| 工具 | 资料来源 | 文件引用的写法 | 行号区间 |
|---|---|---|---|
| Claude Code | 官方文档 *Common workflows → Reference files and directories* | `@path`（相对或绝对路径）。会把**整个文件**放进上下文（上限约 25k tokens，超过 256 KB 的文件不放入） | **没有文档化的行号写法** |
| Codex | `openai/codex` 仓库中的系统提示词（`codex-rs/protocol/src/prompts/base_instructions/default.md`） | 模型输出中的引用格式为 `path:line` 或 `path#Lline`；输入中可以用 `@` 搜索并插入路径 | 明确规定“不要给出行号区间” |
| dsh（DeepSeek Harness） | `deepseek-ai/deepseek-harness` 仓库 `packages/context/file-reference/src/grammar.ts` | `@path`，遇到空白字符即结束；路径中有空格时写 `@"path with spaces"`。只插入路径，不附带文件内容，由模型自己调用读取工具 | 语法中没有行号 |

**结论**：三个工具都**不能解析** `#L41-58` 这类写到路径里的行号区间。尤其是 dsh：`@x.cs#L41-58` 会被当成一个名为 `x.cs#L41-58` 的路径，导致引用失效。所以行号区间必须**写在路径之后、用空格隔开**，作为普通文字交给模型理解。

## 2. 默认格式（修订 UX_SPEC §5.3）

```
@{path} (lines {start}-{end})
```

- 路径中有空格时，写成 `@"{path}" (lines {start}-{end})`（dsh 的语法；另外两个工具是否支持，需要实测）
- 路径是相对于工作区根目录的路径，用 `/` 分隔
- 一段对应一行

**两种导出方式的区别**（写在篮子视图的提示中）：
- **复制为引用**：只给出路径和行号，由 AI 工具自己去读文件。适合 AI 工具的工作目录就是这个项目时。注意：Claude Code 会把整个文件放进上下文，对很大的文件，行号只能起提示作用。
- **复制为 Markdown**：把代码内容直接带过去。适合只想让 AI 看这几段代码、或者 AI 工具的工作目录不是这个项目时。

## 3. 实测清单（需要你在三个桌面版中各测一次）

准备：在 AI 工具中打开测试项目（工作目录为项目根目录），从 Rove 的篮子复制出引用，粘贴到输入框后发送。

| # | 粘贴的内容 | 观察什么 | Claude Code | Codex | dsh |
|---|---|---|---|---|---|
| 1 | `@Assets/Scripts/Player.cs (lines 41-58)` | 是否被识别为文件引用（显示为文件标签或附件）；模型是否读取了正确的文件，并关注到指定的行 | | | |
| 2 | `@"Assets/Standard Assets/Foo.cs" (lines 1-10)` | 带空格的路径能否识别 | | | |
| 3 | 一条消息中包含 3 行引用 | 多个引用是否都能识别 | | | |
| 4 | 含中文的路径 | 能否识别 | | | |
| 5 | 绝对路径 `@D:/.../Player.cs (lines 41-58)` | 工作目录不是这个项目时，能否读到文件 | | | |

根据实测结果：如果三个工具的表现一致，就只保留一个默认格式；如果不一致，就为不一致的工具提供单独的预设（`rove.contextBasket.referenceTemplate` 的下拉选项）。
