# 高 DPI 与多显示器人工验收清单（#30）

自动化部分已经进 `cargo test --workspace`（见本文末「自动化覆盖」）。**这一份只列必须人工执行的检查**：
截图类的观感判断、以及必须用两块不同缩放比显示器才能复现的场景（不能用模拟代替，这正是 M0 悬空的那一项，
见 [M0_UI_SPIKE_REPORT](M0_UI_SPIKE_REPORT.md) §4.6 / §8 第 1 条）。

## 0. 准备

- Windows 11，两块显示器，缩放比设成不同值（例如主屏 150%、副屏 100%）。
- `cargo build --release -p rove-app` 后运行 `rove.exe`，打开一个 Unity 项目（`ROVE_TEST_UNITY_MEDIUM`）。
- 准备一个混排文件：ASCII + 中文 + 日文 + 韩文 + emoji（含 ZWJ 家庭、肤色修饰）+ Tab 缩进 + 一条超长行。
  `crates/rove-ui/tests/code_view_dpi.rs` 的 `mixed_patterns()` 就是这组样例，可以直接复制成 `.cs` / `.md`。
- 每一项都截图存档（文件名建议 `dpi-<缩放>-<检查项>.png`）。改系统缩放后**重新登录**再测一次，
  避免只测到了运行中动态变更这一条路径。

## 1. 缩放比例矩阵（100% / 125% / 150% / 200%，每档都做）

| # | 检查项 | 判据 | 结论 |
|---|---|---|---|
| 1.1 | 文字清晰度 | 次像素定位与 gamma 正常，无发虚、无重影；中文与 emoji 的字体回退正常 | |
| 1.2 | 命中测试 | 点击任意字符落到正确行列；CJK 全角、Tab、emoji 混排时误差 ≤ 1 个字符 | |
| 1.3 | 插入符 | 位置与宽度正确，不出现半像素虚线；闪烁时粗细不变 | |
| 1.4 | 滚动条 | 轨道与滑块尺寸正常；拖动与点击跳转的命中区与看到的一致 | |
| 1.5 | 行号栏 / 缩进参考线 / 分隔线 | 1 物理像素的线条不消失、不发虚、不变成 2 px | |
| 1.6 | 浮层 | 快速打开、命令面板、菜单、通知、查找条、面包屑选择器、悬停卡片的位置与尺寸正确，不越界、不被裁切 | |
| 1.7 | 图标 | codicons 字体在各缩放下不糊 | |
| 1.8 | Markdown 预览 | 预览与宿主的缩放一致，没有两套缩放叠加（正文字号与源码视图观感一致） | |

> 1.5 的判据对应代码里的 `rove_ui::dpi::{hairline, snap}`：细线宽度恒为 1 个物理像素、边界对齐到物理像素
> 网格。用截图工具放大到像素级看：线应当是一列实色像素，而不是两列半透明像素。
> 注意 `div` 的 `border_1()` 类边框仍然是 1 **逻辑**像素（与 VS Code 的 CSS `1px` 同口径），在 150% 下
> 本来就是 1.5 物理像素，只要不出现断续或明显糊成两列即可。

## 2. 多显示器与跨屏拖动（必须两块不同缩放比的显示器）

| # | 场景 | 判据 | 结论 |
|---|---|---|---|
| 2.1 | 窗口在任一屏上打开 | 布局正确，字号观感一致 | |
| 2.2 | 从 A 屏拖到 B 屏 | 收到缩放变更事件后重新布局；滚动位置与选区不变；没有闪烁或一帧错位 | |
| 2.3 | 拖过去再拖回来 | 回到原样；反复拖十次不累积漂移 | |
| 2.4 | 拖动后再点击 | 命中仍然准确（误差 ≤ 1 个字符） | |
| 2.5 | 窗口横跨两屏各一半 | 不出现尺寸抖动、不反复重建（观察任务管理器里进程数与 CPU 占用是否异常） | |
| 2.6 | 副屏上开浮层 | 快速打开 / 命令面板 / 菜单 / 通知位置正确，不跑到主屏上 | |
| 2.7 | 副屏上开 Markdown 预览 | 预览跟着窗口走，缩放与宿主一致；拖回主屏后仍然一致 | |
| 2.8 | 最大化状态下跨屏 | 与 2.2 相同判据（`WM_DPICHANGED` 在最大化时不发 `WM_SIZE`，走的是另一条代码路径） | |
| 2.9 | 运行中改系统缩放 | 在「设置 → 显示」里改缩放，窗口当场重排，不需要重启 | |

## 3. 与字体缩放叠加

| # | 场景 | 判据 | 结论 |
|---|---|---|---|
| 3.1 | `Ctrl+=` / `Ctrl+-` / `Ctrl+0`（`editor.action.fontZoom*`） | 行高、命中测试、滚动条都跟着变且保持正确 | |
| 3.2 | `editor.fontSize` 改成 10 / 24 | 同上 | |
| 3.3 | `window.zoomLevel`（放大 / 缩小窗口）与系统缩放叠加 | 界面整体放大，Markdown 预览跟着放大且只放大一次 | |
| 3.4 | 上面三者 + 150% 系统缩放同时生效 | 仍然正确，没有累乘错误 | |

## 4. 输入法（与 #5 的补丁相关）

| # | 场景 | 判据 | 结论 |
|---|---|---|---|
| 4.1 | 在 150% 下输入中文 | 候选框跟随插入符（`ImmSetCandidateWindow` 用的是物理客户区坐标） | |
| 4.2 | 跨屏拖动后继续输入 | 候选框仍然跟随，不偏到另一块屏上 | |

## 5. 自动化覆盖（不用人工重复）

| 范围 | 测试 |
|---|---|
| 四档缩放下布局尺寸、行高、字号、可见行范围、每个字素簇边界的 x 完全一致 | `cargo test -p rove-ui --test code_view_dpi` |
| 四档缩放下「像素坐标 → 行列」精确往返（CJK / Tab / emoji / ZWJ / 肤色修饰），含真实鼠标事件 | 同上 |
| 缩放变更事件**当场**清空整形缓存；拖过去再拖回来几何不漂移；滚动位置与选区不变 | 同上 |
| 字体缩放命令、`editor.fontSize` 与系统缩放叠加后行高与命中测试仍然正确 | 同上 |
| 物理像素对齐的换算（细线恒为 1 物理像素、插入符取整数个物理像素） | `cargo test -p rove-ui dpi::` |
| 浮层（快速打开 / 命令面板）在四档缩放下位置尺寸不变、不越界不被裁切 | `cargo test -p rove-ui quick_input_overlay` |
| Markdown 预览的 `RasterizationScale` 跟随窗口、网页缩放只来自 `window.zoomLevel`（不叠加） | `cargo test -p rove-ui preview_scale` |

GPUI 测试窗口的缩放系数由 `VisualTestContext::simulate_scale_factor_change` 驱动（vendor 补丁，见
[`vendor/gpui/ROVE_PATCHES.md`](../vendor/gpui/ROVE_PATCHES.md) 的 R30 条目）。它模拟的是
`WM_DPICHANGED` 之后窗口逻辑尺寸不变、缩放系数改变这一路径；**真实的混合 DPI 多显示器仍然必须人工验证**。
