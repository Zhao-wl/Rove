## 阶段 1–5：里程碑

每个里程碑结束时，都要能得到一个可以实际使用的版本。

| 里程碑 | 目标 | 包含（来自 FEATURES.md 的 P0/P1） | 完成标准 |
|---|---|---|---|
| **M1 只读阅读器** | 能代替 VS Code 来“看代码” | 工作台骨架（标题栏、活动栏、侧边栏、编辑器组网格、面板、状态栏、通知）；代码视图（只读：高亮、行号、折叠、括号匹配、面包屑、同名高亮的文本版本、字体缩放、超大文件）；与 VS Code 共用设置和键位文件（D4）、加载 VS Code 主题；资源管理器；快速打开与命令面板；当前文件查找；全局搜索；大纲；Markdown 预览 | 在两个 Unity 测试项目中，日常“看代码”不需要再打开 VS Code；性能指标达标 |
| **M2 C# 导航** | 跳转和引用体验超过 VS Code | 索引工程化（格式 v2、性能优化、增量、生命周期管理、L1 快速索引、查询路由）；转到定义、查找所有引用（速览窗口，D3）、速览定义、悬停、导航历史、语义级同名高亮、转到文件中的符号；元数据视图 | 导航准确率测试集通过；响应时间指标达标 |
| **M3 轻编辑** | 能放心地做局部修改 | 输入、IME、撤销重做、单词操作、查找替换、保存（保持编码和换行符）、外部修改重载 | IME 场景全部通过；编码往返零差异 |
| **M4 体验补全** | 补齐首版的 P1 功能 | 粘性滚动、引用视图（侧边备选）、缩略图、概览标尺、括号对着色、多光标、行操作、智能扩选、注释切换、自动缩进与自动闭合、JSON/XML 格式化、结构树、图片预览、转到实现、工作区符号、语义高亮、资源管理器中的文件操作、全局替换、中英文界面、热退出、Zen 模式 | FEATURES.md 中所有 P1 项完成 |
| **M5 发布** | 可以分发给团队使用 | 安装包、索引组件打包、版本握手、体积守护、第三方许可声明 | 在一台干净的 Windows 上能安装并使用 |
| 以后 | P2 待办 | 调用层级与类型层级、引用数量提示、本地历史、对比视图、搜索编辑器、辅助侧边栏、macOS 移植…… | 按需排期 |

**为什么是这个顺序**：
- “阅读”是核心价值，所以 M1 先交付只读阅读器；
- C# 导航是相对 VS Code 的主要差异点（响应更快、不需要常驻语言服务），所以排在 M2；
- 编辑排在阅读之后，这是你确定的优先级；
- 体验补全放在三项核心能力都可用之后。

## 贯穿始终的工程要求

- **性能预算守护**：从 M1 开始，CI 中就要有基准测试，指标见立项文档 §6。
- **核心层不依赖 UI**：只有 `rove-ui` / `rove-app` 可以依赖 `gpui`。
- **与 VS Code 的行为一致性测试**：对移植的算法（模糊匹配打分、单词边界、缩进规则等），用 VS Code 自带的测试用例作为测试数据，逐条对照。
- **第三方许可**：所有移植内容都记录在 `THIRD_PARTY_NOTICES.md` 中。
