## 背景

v0.1 是 Rove 第一个可发布版本（`docs/MILESTONE_v0.1.md`）：M1–M3 全部完成，加上提前的 R51（多光标与行操作）、R52（注释切换、自动缩进、自动闭合、包围、回车规则）、R54（粘性滚动）、R57（软换行）、R59（转到类型定义、工作区符号、侧边引用视图）、R73（精简 GPUI 的网络依赖），以及发布流水线 R75（Windows 发布流水线、安装包、体积守护、第三方许可声明） 和自动更新 R76（自动更新）。

R31（【集成验收】M1）、R44（【集成验收】M2）、R50（【集成验收】M3） 各自验收了自己的里程碑，但没人看过**这些东西叠在一起、装在一台干净机器上、再被自动更新升级一次**之后是什么样子。本 issue 就做这件事：通过之后打 `v0.1.0` tag。

本 issue 由**一个会话独占**，开始前所有前置 issue 与 GitHub 里程碑「v0.1 首发」中的跟进 issue 都已关闭。产出是 `docs/V01_ACCEPTANCE_REPORT.md` 和对接缝缺陷的修复。

必读：`docs/MILESTONE_v0.1.md`（范围与发布门槛）、`docs/M1_ACCEPTANCE_REPORT.md`、`docs/M2_ACCEPTANCE_REPORT.md`、`docs/M3_ACCEPTANCE_REPORT.md`（三份基线）、`PROJECT_CHARTER.md` §2.1 与 §6、`docs/issues/COVERAGE.md`（「v0.1」列为「是」的行）。

### 3. 干净机器上的安装与自动更新

- 干净的 Windows 10 与 Windows 11 x64 虚拟机（不装 VS Code、.NET、WebView2）各走一遍：运行 v0.1.0 安装包（记录 SmartScreen 提示的放行步骤） → 启动 → 打开 Unity 项目 → 读代码、跳转、改代码、保存 → **留一处未保存的修改**。
- 发布一个演练用的 v0.1.1（可以用测试仓库，避免污染正式 Release）→ 等 R76（自动更新） 自动检查、下载、提示 → 重启更新 → 确认版本号、未保存的修改与会话原样恢复、C# 索引组件同步升级。
- 卸载：程序目录、快捷方式、注册表项清除；用户数据按选项保留或删除。

### 4. 网络监视

全程监视一次完整会话（启动 → 打开两个项目 → 走完第 2 节 → 退出），口径写进报告：

- `rove.update.mode = "none"`：`rove.exe`、索引进程、WebView2 进程树**零出站连接**；
- `rove.update.mode = "default"`：只出现到 `github.com` / `objects.githubusercontent.com` 的 HTTPS 连接，且只发生在检查与下载时；
- R73（精简 GPUI 的网络依赖） 的编译期检查仍然生效。

### 5. 性能预算

`perf/budgets.toml` 中**不允许还有 `pending` 条目**：每一条都已 `enforced` 且达标，或按章程流程修订了口径。在空闲机器上跑一遍 `cargo xtask bench --check-budgets` 与 `cargo xtask startup`，与 M1–M3 的基线对照，注明机器负载。
