## 背景

上下文篮子是 Rove 唯一一个「VS Code 里没有、立项时就要的」功能（`PROJECT_CHARTER.md` §4.4、`FEATURES.md` §9，判定为新增、P1）：阅读时把多段代码（可以跨文件）收集起来，整理成结构化文本复制到剪贴板，交给外部 AI 工具。**Rove 不把任何内容发送到任何地方**，只负责整理和复制（`PROJECT_CHARTER.md` §2 非目标）。

`UX_SPEC.md` §5 是这个功能的完整规格——入口、视图、自动合并、位置跟随、按工作区持久化、两种导出格式，全都已经定稿。本 issue 就是把 §5 实现出来，不需要再做交互设计。引用格式另有 `docs/compat/REFERENCE_FORMATS.md`：默认格式已经定了，但**三个工具的真机实测（0.3d）尚未完成**，所以本 issue 的做法是「把模板做成设置项 + 发默认值」，不预先铺开按工具预设。

必读：`UX_SPEC.md` §5 全节、§6.1（反馈分级）、§6.3（空状态）；`FEATURES.md` §9（上下文篮子一行）、§2（活动栏 P1 加篮子入口）；`docs/compat/REFERENCE_FORMATS.md` 全文；`docs/compat/KEYBINDINGS.md` §5（五条 `rove.contextBasket.*` 命令）；`docs/compat/SETTINGS.md` §4（`rove.contextBasket.referenceTemplate` / `contextLines` / `clearAfterCopy`）；`THEME_COLORS.md`（Lists and trees、Side Bar、Activity Bar 的徽标）。

## 目标

### 1. 条目模型与持久化

- 一个条目 = 文件路径 + 行区间 + 所属符号 + 备注；**记录位置，不记录快照**（§5.2），导出时读文件的当前内容。
- 篮子**按工作区保存**，重启后仍在，保存在 Rove 自己的状态目录、**不写入项目目录**：`%LOCALAPPDATA%\Rove\state\<工作区路径哈希>\basket.json`。这个「工作区状态目录」的约定与 R16（工作台） 的布局持久化共用同一个根，**开工时与 R16（工作台） 对齐一次**。
- 写入是原子的（临时文件 + 重命名），损坏或版本不认识时丢弃并重新开始，不阻塞启动。

### 2. 加入篮子的入口（§5.1）

| 入口 | 加入的内容 | 来源 issue |
|---|---|---|
| 编辑器右键菜单 / `rove.contextBasket.add`（`ctrl+k b`，when `editorTextFocus`） | 有选区：选中的行区间（多光标时每个选区各成一段）；无选区：光标所在的**符号**整体范围 | R19（代码视图 Element）、R26（大纲） |
| 资源管理器右键菜单 | 整个文件（支持多选） | R23（资源管理器） |
| 大纲右键菜单 | 该符号的完整范围 | R26（大纲） |
| 速览结果列表右键菜单 | 该引用位置 + 前后各 `rove.contextBasket.contextLines`（默认 3）行 | R41（速览窗口） |
| 搜索结果右键菜单 | 命中行 + 前后各 N 行，或整个文件 | R25（全局搜索） |
| Markdown 预览中的选区 | 映射回源码中对应的行区间 | R29（Markdown 预览） |

- 「光标所在的符号」通过 R26（大纲） 的符号树查询（R01（【接口先行 A1】架构与接口契约） 已把符号树定为共用类型），不自己解析语法；查不到符号时退化为当前行并在状态栏说明。
- 这些菜单项由**本 issue 通过 R01（【接口先行 A1】架构与接口契约） / R16（工作台） 的菜单与命令登记机制注册到对应视图**，不去改那几个 issue 的代码（登记以外的改动一律不做）。Markdown 预览的「预览选区 → 源码行」映射复用 R29（Markdown 预览） 的滚动同步行映射；如果那条映射没有对外暴露，走契约变更流程单独提小 PR，不在本 PR 里改 R29（Markdown 预览）。
- 加入后：活动栏图标显示条目数徽标 + 状态栏临时消息「已添加到上下文篮子（共 4 段）」。**不弹通知、不切换视图**（§5.1）。

### 3. 篮子视图（§5.2）

通过 R16（工作台） 的视图登记机制在活动栏追加一个视图容器（`FEATURES.md` §2：P1 加上下文篮子），列表与拖动排序复用 R18（通用列表、树与快速输入组件）：

- 顶部「说明」输入框（选填，导出时放在最前面）。
- 条目行：序号、相对路径、行号区间、所属符号（如 `Player.Move(Vector3)`）、代码前两行预览、备注（点击即可编辑）。
- 条目操作：点击 → 通过 R17（编辑器组与标签） 的打开文档服务定位并高亮该区间；拖动调整顺序；悬停出现「编辑备注」「删除」。
- 底部统计：总行数、总字符数、**在本地按字符数估算的 token 数**（不调用任何服务）；**超过 10 万字符时数字变为警告色**。
- 底部按钮：**复制为 Markdown**（主按钮）、复制为引用、清空，分别对应 `rove.contextBasket.copyAsMarkdown` / `copyAsReferences` / `clear`；`rove.contextBasket.focus`（`ctrl+shift+alt+b`）聚焦视图。
- 空状态照搬 §6.3：「选中代码后，右键选择'添加到上下文篮子'，或者使用快捷键。」加一张简短示意图。

### 4. 自动合并与位置跟随（§5.2）

- 同一文件中**重叠或相邻**的区间自动合并，备注一并合并（顺序保持先加入者在前）。
- 文件被编辑时区间跟随平移（M3 的编辑事务已经存在时接 R45（编辑核心模型） 的位置映射；只读阅读场景下主要靠外部改动）。
- 外部大幅修改导致无法可靠跟随时，条目标记「**可能已过期**」，点击后可以重新选择范围；文件被删除时标记「**文件已删除**」，导出时跳过。判定依据来自 R15（工作区） 的文件事件 + 行数 / 内容指纹，不轮询磁盘。
- 文件被重命名时条目跟到新路径（与 R62（资源管理器文件操作） 约定：以 R15（工作区） 的重命名事件为准）。

### 5. 导出格式（§5.3、REFERENCE_FORMATS）

**复制为 Markdown**（主按钮）：按 §5.3 的样板输出——说明段（为空时省略）、每段 `## 序号. 相对路径:起-止 · \`符号\``、备注（为空时省略）、带语言标记的代码块。规则逐条实现：

- 路径相对工作区根、用 `/` 分隔；行号从 1 开始；
- 代码块语言标记取自当前文件的语言模式（来自 R12（语言配置） / R72（语言检测） 的语言 ID）；
- **换行符统一为 LF、编码统一为 Unicode**（源文件是 GBK / CRLF 时也一样）；
- 代码内部本身含 ``` 时**自动加长外层围栏**。

**复制为引用**：每段一行，格式来自 `rove.contextBasket.referenceTemplate`，默认 `@{path} (lines {start}-{end})`；路径含空格时写成 `@"{path}" (...)`（dsh 的语法）。模板的占位符（`{path}`、`{start}`、`{end}`）要有校验与一条可定位的错误提示，模板非法时回落到默认值。

**复制之后**：状态栏临时消息「已复制 3 段内容（约 2.1k tokens）」；`rove.contextBasket.clearAfterCopy`（默认 false）决定是否清空。

### 6. 登记与替换

命令、设置项、颜色键、界面字符串、视图容器与活动栏徽标全部通过 R01（【接口先行 A1】架构与接口契约） 与 R16（工作台） 的登记机制加入，不得写死。R02（【接口先行 A2】行走骨架） 中没有本 issue 对应的 `SKELETON(...)` 标记，只在 `docs/ARCHITECTURE.md` 中新增自己的一行。不得在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口。GPUI 类型只出现在 `rove-ui` / `rove-app`。

## 风险与提示

- **位置跟随是本 issue 最难的部分**。"条目记录位置而不是快照"听起来简单，但文件在外部被整体重写（Unity 重新生成、git 切分支）时，任何行号都可能失效。宁可**保守地标记「可能已过期」**，也不要导出错位的代码——导出错位的代码比报告过期更糟，用户不会逐行核对。
- 导出格式的细节（围栏加长、LF 统一、路径分隔符）每一条都有对应的真实 bug 场景，验收标准里逐条列了，不要合并成一条「导出正确」。
- `REFERENCE_FORMATS.md` 的实测是**阻塞「按工具预设」而不是阻塞本 issue** 的。不要因为等实测而不开工，也不要凭推测给三个工具各写一套格式。
- 菜单入口分散在六个别人负责的视图里，是最容易写成「顺手改一下那边的代码」的地方。严格只用登记机制；发现某个视图缺少登记点，按契约变更流程单独提小 PR。
- token 估算只能是粗略的字符数换算，文案里已经写了「约」。不要为了更准而引入任何分词模型或网络请求。
