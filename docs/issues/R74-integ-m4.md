## 背景

M4 有 24 个前置 issue，横跨编辑交互、阅读增强、文档视图、外观、发布前的工程整理。它们各自的测试只覆盖自己那一块，而 M4 的风险恰恰在**叠加**：缩略图 + 粘性滚动 + 括号对着色 + 语义高亮同时开着时，每帧 CPU 还能不能守住 1 ms？大文件级别该关掉的功能，在四个新功能加入后是不是真的都关掉了？切到英文界面后，这一批新增的界面还有没有没登记的中文字面量？精简掉 GPUI 的网络依赖之后，运行期是不是真的一个包都不发？

本 issue 由**一个会话独占**，开始前 M4 的全部前置 issue 都已合并。产出是一份可核对的验收报告和对接缝缺陷的修复。

`PLAN.md` 的 M4 完成标准是一句很短的话：**`FEATURES.md` 中所有 P1 项完成**。本 issue 负责逐条证明或证伪它——包括那些**不在 M4 的 24 个键名里、但在 `FEATURES.md` 里标着 P1** 的条目（例如 §9 的「Markdown 大纲、链接跳转」，R29（Markdown 预览） 已明确把「链接跳转与路径补全」排除在外）。对照时发现无主的 P1 项，**开 issue 并在报告中列明，不要在本 PR 里顺手实现**。

必读：`PLAN.md`（M4 一行）、`FEATURES.md` 全文（逐条核对 P1）、`UX_SPEC.md` 全文、`PROJECT_CHARTER.md` §6（性能指标）与 §7（Windows 专项风险）、`docs/compat/*`、`docs/M0_UI_SPIKE_REPORT.md` §4.4（滚动帧预算）与 §4.7（依赖）、`docs/M1_ACCEPTANCE_REPORT.md`、`docs/M2_ACCEPTANCE_REPORT.md`、`docs/M3_ACCEPTANCE_REPORT.md`（三份基线）。

### 3. 分级降级逐项核对（`UX_SPEC.md` §3.1）

M4 新增的功能里有一半出现在「大文件要关掉」的清单里，这是本里程碑最容易漏的地方。按表逐项断言：

- **大文件（≥ 20 MB 或 ≥ 30 万行）**：关闭缩略图、粘性滚动、括号对着色、同名高亮、语义高亮、基于语法的折叠（**保留基于缩进的折叠**）；语法高亮在后台完成，完成前显示纯文本。
- **超大文件（≥ 64 MB，`rove.largeFile.threshold`）**：在上面基础上再关闭语法高亮、所有折叠、软换行、替换；整体只读。
- `editor.largeFileOptimizations` 为 false 时不启用「大文件」这一级。
- 每一项都要有断言，而不是「看起来没开」。

### 4. 性能回归核对

用 R04（性能基准与预算守护） 的工具链在参考设备（8 核 / 16 GB / SSD / 集显）上实测，与 `perf/budgets.toml` 及 M1–M3 的基线对比，每项给出中位数与 p99：

| 指标 | 预算 | M4 的新增压力 |
|---|---|---|
| 连续滚动每帧 CPU | < 1 ms | **缩略图 + 粘性滚动 + 括号对着色 + 语义高亮 + 概览标尺全部开启**时重测（M0 原型基线 823 µs，余量很小） |
| 冷启动到可交互 | < 400 ms | 新增扩展主题扫描、图标主题字体加载、设置项登记增多 |
| 空窗口常驻内存 | < 60 MB | 新增字体与图标资源 |
| 打开 1 GB 文件 | < 1 s，滚动稳定 | 软换行与分级降级的交互 |
| 按键到上屏 | < 8 ms | 多光标、自动闭合、自动缩进 |
| 快速打开每次按键 | < 16 ms | 设置项与命令数量增加后的模糊匹配 |
| 定义跳转 / 查找引用 / `F12` 端到端 / 速览首次绘制 / 单文件增量更新 | < 16 ms / < 50 ms / < 50 ms / < 100 ms / < 300 ms | 加入语义高亮装饰后重测，确认 M2 的结论没有回退 |
| 发布包体积 | < 30 MB | 随包资产增多（Seti 字体、grammars）；R75（Windows 发布流水线、安装包、体积守护、第三方许可声明） 的守护尚未合并，本 issue 先给出当前数字 |

超预算的项写明差距、原因与后续 issue，**允许得出未达标的结论**。

### 5. 运行期无网络访问的实测

- 用网络监视工具（资源监视器 / `netstat -b` 轮询 / ETW 抓取，任选并在报告中写明口径）**全程监视一次完整会话**：启动 → 打开两个项目 → 走完场景 1–23 → 退出。要求 `rove.exe` 与索引进程**没有任何出站连接**（WebView2 进程在 Markdown 预览中的行为单独记录：远程资源应被 `rove.markdown.allowRemoteResources=false` 拦截）。
- 与 R73（精简 GPUI 的网络依赖） 的编译期检查对照：`cargo tree` 中不出现 HTTP/TLS 栈，CI 的依赖检查生效。
- 特别检查几处容易偷偷联网的地方：SVG 中的远程引用（R63（图片预览））、扩展图标主题的字体 `src`（R68（只读加载 VS Code 扩展主题、Seti 文件图标主题））、Markdown 中的远程图片与 Mermaid / KaTeX（R29（Markdown 预览））、链接检测（R71（链接检测与打开），**只打开不预取**）。

### 6. 界面字符串完整性

- `cargo xtask i18n-check` 全绿（缺键、占位符不一致、硬编码字面量三项），并在报告中给出两份表的键数。
- 英文界面下的截图覆盖 M4 新增的全部界面：结构树、问题面板、图片预览、上下文篮子、设置界面、Zen 模式、图标主题选择器、跟随末尾的状态栏条目。

### 7. `SKELETON` 标记审计

M4 是最后一个功能里程碑，所以口径比前两次更硬：**整个仓库不应再存在任何 `SKELETON(...)` 标记**，`docs/ARCHITECTURE.md` 中「最简实现 → 负责替换的 issue」的对照表应当全部标为已替换，并与代码一致。还有残留的，要么在本 issue 中补掉，要么开 issue 并在报告中列明。

### 8. 修复接缝缺陷

- 只修**接缝性质**的小缺陷（装饰叠加的顺序不对、分级降级漏关一项、状态没同步、空状态文案不对、命令 / 设置项 / 颜色键 / 字符串漏登记等）。
- 牵涉某个 issue 核心实现的较大问题，**开新 issue** 并在报告中记录，不在本 PR 里重写别人的模块。
- 发现接口缺陷时按契约变更流程单独提小 PR，**不在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口**。
- 修复中新增的任何命令、设置项、颜色键、界面字符串，一律通过 R01（【接口先行 A1】架构与接口契约） 的登记机制加入。

### 9. 扩展端到端测试套件

把场景清单中**可自动化的部分**加进 `cargo test --workspace`（至少覆盖：分级降级的逐项断言、多光标撤销单元、全局替换的一次撤销、结构树与问题面板、篮子的导出格式、跟随末尾的暂停与恢复、热退出恢复、语言切换、设置界面的写入、图片编辑器类型解析）。不可自动化的部分（截图、网络监视、崩溃恢复、真实扩展主题）以清单 + 截图形式记录在报告中。R02（【接口先行 A2】行走骨架） 的端到端测试必须继续通过。

### 10. 产出 `docs/M4_ACCEPTANCE_REPORT.md`

内容：环境信息（机器配置、显示缩放、两个 Unity 项目的版本与规模、本机安装的 VS Code 扩展主题清单）、**`FEATURES.md` P1 逐条对照表**、场景清单逐条结果、分级降级核对表、性能实测表与 M1–M3 基线对照、网络监视结论与口径、i18n 完整性数据、`SKELETON` 审计结果、本 issue 修复的缺陷清单、开出的后续 issue 清单（含无主的 P1 项），以及对 `PLAN.md` M4 完成标准的明确结论。

## 风险与提示

- **帧预算是本里程碑最可能失守的指标**。M0 原型在只有基础渲染时就用掉了 823 µs，而 M4 一次性往每帧里加了缩略图、粘性滚动、括号对着色、语义高亮和概览标尺。测的时候要分别给出「全开」「逐项关闭」的数字，才能定位是谁吃掉了预算——只报一个「超了」对后续 issue 毫无帮助。
- 第二个高风险点是**装饰的叠加顺序**：同名高亮、语义高亮、括号对着色、搜索命中、选区、活动缩进参考线会落在同一行上。顺序错了不会崩，只会「颜色看起来怪怪的」，所以必须用固定主题 + 固定文件做截图对照，不能靠肉眼巡视。
- 分级降级是**反向验收**：要证明某个功能「没有生效」，比证明它生效更容易漏。建议为每一项写一条断言，而不是打开一个大文件看一眼。
- 网络监视要在**干净的时间窗**里做：Windows 自身、输入法、杀毒软件都会产生连接，报告里要写清楚是按进程过滤的，否则结论不可信。
- 英文界面不是「翻译完了就行」：M4 新增界面多，很容易出现只在某个错误分支才显示的中文文案。`i18n-check` 的硬编码字面量检查比人工巡视可靠，优先靠工具。
- 不要把「顺手改好一点」带进这个 PR。本 issue 的价值是**如实记录**与修接缝；一份诚实的未达标清单比一份好看的报告有用得多（参考 `M0_UI_SPIKE_REPORT.md` §8 的写法）。
- 场景 19 需要本机装有 VS Code 与若干主题扩展。没有时手工在 `%USERPROFILE%\.vscode\extensions` 下放几个真实扩展目录来模拟，并在报告中注明。
