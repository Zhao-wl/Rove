## 背景

2026-11-13 定下首个可发布版本 v0.1（`docs/MILESTONE_v0.1.md`）：M1–M3 加上部分 M4 条目先发布，**之后的功能通过自动更新推送**。这改变了一条贯穿始终的硬约束，章程已同步修订（`PROJECT_CHARTER.md` §2.1、`FEATURES.md` §7「自动更新」一行与 D11）：

> 运行时不发起任何网络请求，**唯一的例外是自动更新通道**。

所以本 issue 是全程序**唯一允许联网的地方**。它的设计首先要让人放心：联网代码集中在一个 crate 里、请求的内容一眼能看清、`rove.update.mode = "none"` 时一个连接都没有。

当前只有维护者本人使用：**不做 Authenticode 代码签名、只有一个稳定通道**。安全性靠 ed25519 签名的更新清单加 SHA256 校验保证。

必读：`PROJECT_CHARTER.md` §2.1，`FEATURES.md` §7（自动更新一行）、§12 D11、§13（`rove.*` 命名空间与 `%LOCALAPPDATA%\Rove` 目录约定），`docs/MILESTONE_v0.1.md` §6，R75（Windows 发布流水线、安装包、体积守护、第三方许可声明） 的第 8 节（静默升级参数与 `latest.json` 的生成），R49（热退出与崩溃恢复）（重启前保存会话），R73（精简 GPUI 的网络依赖）（GPUI 里没有 HTTP 客户端，本 issue 不能把它加回去），R43（索引组件打包与版本握手）（索引组件的安装位置与版本握手）。

## 目标

### 1. 独立的更新 crate

- 新建核心层 crate `rove-update`（**不依赖 gpui**，按 `AGENTS.md` §2 登记）：清单解析、签名校验、版本比较、下载、状态机都在这里，界面接线放在 `rove-app` / `rove-ui`。
- 网络用 Windows 自带的 **WinHTTP**（`windows` crate），不引入 reqwest / hyper / rustls / tokio / ring；HTTPS 走系统证书库与系统代理设置。在 PR 中给出 `rove.exe` 体积变化（`cargo xtask check-size`）。
- 在 CI 的依赖检查里加一条：除 `rove-update` 外，任何 crate 都不得依赖 WinHTTP / WinINet / 套接字相关的 feature（具体做法在 PR 中说明，例如检查 `windows` crate 的 feature 是否只在 `rove-update` 中打开）。

### 2. 更新清单与校验

- 地址固定为 `https://github.com/Zhao-wl/Rove/releases/latest/download/latest.json`，不允许由设置或环境变量改写（测试用的覆盖只在 `cfg(test)` / 测试专用的环境变量下生效，并在 PR 中写明）。
- `latest.json` 格式由本 issue 定义并写进 `docs/`：`version`、`released_at`、`notes_url`、`installer {url, sha256, size}`、`components.indexer_cs {version, url, sha256, size}`（可选）、`min_version`（可选，低于它时提示必须更新）。
- 清单附 ed25519 签名（`latest.json.sig`），公钥编进 `rove.exe`；签名不对、版本号不能解析、版本号不比当前新，一律当作「没有更新」，只写日志。
- 下载的安装包先核对 `size` 与 `sha256`，不一致时删除并发通知。
- 请求里**不带任何用户数据**：没有设备标识、没有项目信息、没有自定义请求头（User-Agent 固定为 `Rove/<版本>`）。

### 3. 设置与流程

- `rove.update.mode`（`SETTINGS.md` §4 的格式登记；键名加 `rove.` 前缀，避免与共用 settings.json 中 VS Code 的 `update.mode` 冲突）：

| 取值 | 行为 |
|---|---|
| `none` | 从不联网；「检查更新」命令提示更新已关闭 |
| `manual` | 只在执行「检查更新」命令时检查 |
| `start` | 启动时检查一次，有新版本时提示，用户确认后再下载 |
| `default`（**默认**） | 启动后延迟检查（不占冷启动预算），之后每 6 小时检查一次；有新版本时后台下载，下载好后用提示条提示「重启以更新到 x.y.z」 |

- 「重启以更新」：先走 R49（热退出与崩溃恢复） 保存会话与未保存的修改 → 退出 → 以静默参数运行下载好的安装包（参数与 R75（Windows 发布流水线、安装包、体积守护、第三方许可声明） 对齐） → 安装器装完后重新启动 Rove → 恢复会话。全程不弹 UAC（用户级安装）。
- 用户也可以忽略提示，下次正常退出时**不自动安装**；下次启动时如果还是最新的待安装版本，就再提示一次。
- 命令：`update.checkForUpdates`（命令面板与帮助菜单）、`update.restartToUpdate`（有待安装更新时可用）；状态栏不加常驻条目，只用提示条与通知（`UX_SPEC.md` §6 的反馈分级）。
- 「关于」对话框（R75（Windows 发布流水线、安装包、体积守护、第三方许可声明））显示更新状态：已是最新 / 正在下载 / 待重启安装 / 更新已关闭 / 上次检查失败（时间与原因）。

### 4. C# 索引组件的更新

- 只有**已经安装**了组件时才检查组件更新；没安装的不替用户下载（与 R43（索引组件打包与版本握手） 的约定一致）。
- 组件包解压到 `%LOCALAPPDATA%\Rove\components\indexer-cs\<新版本>\`，校验通过后才切换；旧版本在下次启动、确认没有进程在用时再删。版本握手沿用 R43（索引组件打包与版本握手），不另起一套。

### 5. 失败与降级

- 网络不通、超时、GitHub 返回 404 / 403（限流）：静默，只写日志，下次按计划再试；连续失败不弹通知。
- 校验失败、安装器退出码非 0、重启后版本号没变：发通知并保留旧版本继续可用；下载的文件删除。
- 下载放在 `%LOCALAPPDATA%\Rove\updates\`，同时只保留一个待安装版本；磁盘空间不足时放弃并通知。

## 不包含

- 安装器本身、静默升级参数的实现、`latest.json` 的生成与签名（R75（Windows 发布流水线、安装包、体积守护、第三方许可声明））。
- Authenticode 代码签名、多个更新通道（D11：当前只有维护者本人使用；以后需要时再评估）。
- 差量更新：每次都下载完整安装包（主程序 < 30 MB）。
- 便携版的自动更新：便携版只在「检查更新」时提示有新版本并打开 Release 页面，不在自己的目录里替换文件。

## 验收标准

- [ ] `rove-update` 不依赖 gpui；除它之外没有 crate 能发起网络请求，CI 有对应检查
- [ ] `rove.update.mode` 四个取值各有测试；`none` 时用 `netstat` / 资源监视器确认整个会话零连接（记录口径）
- [ ] 清单签名错误、版本号非法、版本号不更新、SHA256 不符、体积不符五种情况各有单元测试，结果都是「不更新」且旧版本不受影响
- [ ] 在干净虚拟机上：装 v0.1.0 → 发布 v0.1.1（可以用测试仓库或预发布的 Release 演练）→ 自动检查、下载、提示 → 重启后是 v0.1.1，未保存的修改与会话原样恢复
- [ ] 已安装 C# 索引组件时，组件随更新升级，旧版本在下次启动后清理；未安装时不下载
- [ ] 冷启动预算不受影响（检查延迟到首帧之后），附 `cargo xtask startup` 前后数据；附 `cargo xtask check-size` 输出
- [ ] 请求内容可审查：PR 中列出全部请求（URL、方法、请求头），日志里每次请求都有一行记录
