## 背景

M3 只有四个 issue，但它改变了 Rove 的性质：从“打开看”变成“动手改”。`PLAN.md` 给 M3 的完成标准是**能放心地做局部修改**，验收口径是两句硬话：**输入法场景全部通过；编码往返零差异**。

风险集中在接缝上，而且这些接缝单元测试都够不着：

1. **输入法**只在 M0 验证过主路径，`M0_UI_SPIKE_REPORT.md` §8 第 6 条如实列出了一串未验证场景；R05（内置 GPUI 0.2.2 并修复 Windows 输入法候选框跟随） 在框架层测过、R46（代码视图的编辑交互与输入法） 在代码视图里测过，但“在一个真实 Unity 项目的 2000 行 `.cs` 里滚到中部、靠着屏幕边缘整句输入中文”这件事没人测过。
2. **编码往返**牵涉 R07（文本缓冲）（识别）、R45（编辑核心模型）（事务）、R48（保存与外部修改）（写回）三方，任何一方的“顺手归一”都会在 `git diff` 里变成整文件差异。
3. **编辑后的联动**牵涉 R09（tree-sitter 集成） 的增量重解析、R20（代码视图） 的高亮刷新、R26（大纲） 的符号更新、R37（L1 快速声明索引） 与 R35（增量索引） 的索引更新、R40（C# 导航交互） 的近似结果呈现——这条链路跨越 M1、M2、M3 三个里程碑。

本 issue 由**一个会话独占**，开始前 R46（代码视图的编辑交互与输入法）、R47（当前文件替换）、R48（保存与外部修改） 都已合并。产出是一份可核对的验收报告与对接缝缺陷的修复。

必读：`PLAN.md`（M3 一行）、`UX_SPEC.md` §3.4–§3.6、§6.1、§6.4，`FEATURES.md` §4、§6，`PROJECT_CHARTER.md` §6 与 §7，`M0_UI_SPIKE_REPORT.md` §5、§8。

## 目标

### 1. 输入法场景矩阵

测试项目通过环境变量指定：`ROVE_TEST_UNITY_MEDIUM`、`ROVE_TEST_UNITY_LARGE`（R03（工程规范与 CI） 的约定）。实机驱动，沿用 `spikes/ime_test.ps1` 的安全阀（注入按键前校验前台窗口句柄，不相等立即中止；结束时还原用户原本的输入法模式）。

| # | 场景 | 判据 |
|---|---|---|
| 1 | 短词输入（`ni'hao`）并提交 | 组合态内嵌带下划线，候选框在插入符正下方，提交内容正确 |
| 2 | **≥ 20 字整句**输入 | 候选框全程跟随插入符，不偏移（R05（内置 GPUI 0.2.2 并修复 Windows 输入法候选框跟随） 修复的直接验收点） |
| 3 | 组合中途用鼠标点到另一行 | 提交或取消二选一，**不留残片**，不崩溃 |
| 4 | 组合中途切换输入法 | 同上 |
| 5 | 插入符靠近屏幕右 / 下边缘 | 候选框翻转，不被裁切 |
| 6 | 全角 / 半角符号、Shift 临时英文 | 字符正确，不吞字 |
| 7 | 在 CJK 与 emoji 混排的长行中部输入 | 插入位置正确，命中测试不漂移 |
| 8 | 125% / 150% 缩放下重跑 1、2、5 | 候选框定位正确（R30（高 DPI 与多显示器验证与修复） 的结论在此复验） |
| 9 | 第三方输入法（搜狗 / 微信） | 条件允许时测；**未安装就如实写“未测”**，不得含糊带过 |

每项附截图；无法截图的（崩溃类）附日志。

### 2. 编码往返零差异（在真实文件上）

从两个 Unity 项目里挑出真实文件（不是构造的测试数据）组成矩阵，每个文件“打开 → 改一处 → 保存”，然后与原文件做**字节级对比**，差异必须恰好等于那一处改动：

- GBK + CRLF（带中文注释的 `.cs`，Unity 项目里很常见）
- UTF-8 带 BOM、UTF-8 不带 BOM
- UTF-16 LE / BE
- **混合换行符**文件（没有现成的就人工构造一个并说明）
- 末尾无换行的文件、空文件、只有一行的大文件
- GBK 文件中输入 emoji 触发无法编码模态框，三个选项各走一遍

### 3. 外部修改风暴与保存冲突

- 脚本连续改写同一文件 **100 次**：最终内容与磁盘一致，提示条不堆积、通知不重复弹（`UX_SPEC.md` §6.1 通用规则）。
- 有本地修改时外部被改：提示条两个选项各走一遍；无本地修改时静默重载且滚动位置与光标不变。
- 保存冲突：通知按钮“比较”隐藏、“覆盖”“放弃本地修改”可用。
- 被 Unity 占用（在 Unity 导入资源期间保存）与只读属性文件（`.meta` 或手工加只读）各走一遍，确认**没有任何管理员提权入口**（`UX_SPEC.md` §6.4）。
- 文件被外部删除后标签标记“已删除”，再保存等同新建。
- 连续保存 20 次，确认自己的写入**一次都没被当成外部修改**。

### 4. 编辑 → 高亮 / 大纲 / 索引的联动

在一个真实 `.cs` 文件里改动一个方法体与一个方法签名，逐段核对：

- R09（tree-sitter 集成） 增量重解析后高亮正确、无闪烁、行高不跳动；
- R26（大纲） 的符号与面包屑随签名改动更新；
- 保存前：R38（查询路由与未保存修改的位置映射） 的查询走未保存修改的位置映射，结果标为**近似**，呈现方式按 `UX_SPEC.md` §2.2（状态栏临时提示 / 悬停底部灰字 / 同名高亮退化为文本高亮且无提示）；
- 保存后：R35（增量索引） 的单文件重绑完成，查询在 **< 300 ms** 内变为精确，并且切换过程中**不重弹提示、不闪烁高亮**（R40（C# 导航交互） 的风险提示）；
- R58（C# 语义高亮与不生效预处理代码置灰）（M4）尚未合并，语义高亮不在本次验收范围。

### 5. 只读强制

`Library/PackageCache/**` 下的文件：打开即只读、锁形图标、尝试输入时光标处提示带原因、替换行不显示、`Ctrl+S` 不产生写入；“在此会话中切换只读”对它有效、对超大文件无效。超大文件（≥ 64 MB）上确认替换入口与编辑入口全部不存在。

### 6. 性能复核

用 R04（性能基准与预算守护） 的工具链在参考设备上实测并与 `perf/budgets.toml` 比对：

- **按键到上屏 p99 < 8 ms**（`PROJECT_CHARTER.md` §6），在 10 万行文件、高亮启用、插入符位于文件中部的条件下取样 ≥ 300 次；
- 输入与替换过程中 R19（代码视图 Element） 的每帧 CPU < 1 ms 不退化（复跑其滚动基准并给出对比）；
- 10 万行文件中替换 ≥ 5000 处的耗时；
- 保存 1 MB 与 10 MB 文件的耗时；
- 单文件索引增量更新 < 300 ms（复用 R35（增量索引） 的口径）。

每项给出中位数与 p99，超预算的写明差距与原因。

### 7. 扩展端到端测试套件

在 R02（【接口先行 A2】行走骨架） 的端到端测试基础上，把上述场景中**可自动化的部分**加进 `cargo test --workspace`，至少覆盖：GBK + CRLF 往返、混合换行符往返、无法编码字符的三条分支、全部替换与撤销、外部修改的三种情况、自己保存不误报、只读文件拒绝编辑、编辑后 `InputEdit` 与变更行区间正确。不可自动化的部分（输入法截图、屏幕边缘翻转、Unity 导入期间保存）以清单 + 截图形式记录在报告中。

### 8. 修复接缝缺陷

- 只修**接缝性质**的小缺陷（状态没同步、提示文案不对、事件去重遗漏、登记遗漏等）。
- 牵涉某个 issue 核心实现的较大问题，**开新 issue** 并在报告中记录，不在本 PR 里重写别人的模块。
- 发现接口缺陷时按契约变更流程单独提小 PR，**不在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口**。
- 修复中新增的任何命令、设置项、颜色键、界面字符串，一律通过 R01（【接口先行 A1】架构与接口契约） 的登记机制加入。

## 风险与提示

- **输入法是本里程碑的头号风险，也是最容易糊弄过去的一项**。只验证“能打出中文”没有意义——`M0_UI_SPIKE_REPORT.md` §8 第 6 条列出的每一条都要单独测，测不了的如实写未测。一份诚实的未达标清单比一份好看的报告有用得多（参考该报告 §8 的写法）。
- 注入按键前务必校验前台窗口。M0 第一次尝试时前台抢夺失败，脚本因为有这个安全阀才没把按键打进别的程序（§5.1）。
- 编码往返要用**真实文件**。构造的测试数据在 R07（文本缓冲） 和 R48（保存与外部修改） 的单元测试里已经覆盖过了；本 issue 的价值在于真实项目里那些奇怪的文件（半截 BOM、GBK 里混着不可见字符、末尾没有换行）。
- 索引联动的时序容易骗人：保存后索引更新是异步的，如果验收脚本在保存后立刻查询，拿到的仍是近似结果，这是**正确行为**而不是缺陷。核对时要分别记录“保存后立刻”和“300 ms 后”两个时间点。
- 不要把“顺手改好一点”带进这个 PR。本 issue 的价值是如实记录。
- Unity 导入期间保存这一项需要能手工触发 Unity 导入（改一个 `.cs` 让 Unity 重新编译）。没有可用的 Unity 环境时，用持有独占句柄的辅助进程模拟，并在报告中注明是模拟而非真实 Unity。
