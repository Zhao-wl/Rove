# R06 WebView2 嵌入验证：遮挡、焦点路由、首开耗时与内存、主题与滚动同步（PLAN 0.2a）

| 里程碑 | 难度 | 领域 | 并行批次 | 前置依赖 | 被依赖 |
|---|---|---|---|---|---|
| M1 只读阅读器 | 4 专家 | ui | 第 1 批 | 无 | R16（工作台）、R18（通用列表、树与快速输入组件）、R29（Markdown 预览） |

> 认领前请阅读 `AGENTS.md`、`docs/ARCHITECTURE.md`（R01 完成后）与 `docs/issues/README.md`。前置依赖全部合并后才能开工。

## 背景

D5 决定 Markdown 预览用系统自带的 WebView2 渲染，这是 Rove 中唯一使用网页内核的地方（`PROJECT_CHARTER` §2、`FEATURES` §12 D5）。`UX_SPEC` §4.3 末尾明确写着：弹出层被预览区域遮挡、焦点路由这两个已知技术风险**必须在 M1 之前完成验证**。这就是 `PLAN.md` 阶段 0.2a。

本 issue 是一次**验证（spike）**，产出是一份报告和一个 go/no-go 结论，不是产品代码。原型放在 `spikes/webview-gpui/`（与 M0 的两个原型一样，通过根 `Cargo.toml` 的 `exclude = ["spikes"]` 排除在 workspace 之外，各自独立 `Cargo.lock`），**不进 `crates/`**，因此不接入 R01（【接口先行 A1】架构与接口契约） 的接口。如果验证结论要求契约里预留什么（例如视图登记需要区分"原生视图"与"宿主窗口视图"），按契约变更流程单独提 PR，不在本 issue 里改。

## 目标

### 1. 最小原型

在一个 GPUI 窗口中嵌入 WebView2，右半边是预览区，左半边是原生绘制的假编辑器。候选方案：`wry` 的子 webview 模式；如果 `wry` 对"嵌入已有 HWND"的支持不顺手，直接用 `webview2-com` 调 `CreateCoreWebView2Controller`。选型理由写进报告。

### 2. 必须验证的四件事（`PLAN.md` 0.2a）

| # | 验证项 | 必须给出的结论 |
|---|---|---|
| ① | **遮挡** | 命令面板、汉堡菜单、悬停卡片、通知与预览区域重叠时，WebView2 是否盖住原生层。Windows 上子 HWND 处于窗口合成的上层，默认一定会遮挡；必须给出可行的规避方案并实测（候选：重叠时临时隐藏或缩小 webview、把弹出层做成独立的顶层窗口、改用 WebView2 的 visual hosting / 合成模式把内容渲染到我们自己的视觉树） |
| ② | **焦点与键盘路由** | webview 获得焦点时，`Ctrl+P`、`Ctrl+Shift+P`、`Ctrl+Shift+V`、`Esc`、`Tab` 能否回到 Rove；Rove 的键位分发与 webview 内部快捷键（`Ctrl+F` 查找、`Ctrl+R` 刷新、右键菜单、DevTools）如何划分；哪些必须禁用 |
| ③ | **首开耗时与内存** | 冷/热首次创建 WebView2 的耗时、常驻内存增量、进程数量。必须回答：按需创建是否真的不影响冷启动 < 400 ms；预览打开后是否还守得住"空闲 < 60 MB"的口径（并说明该口径此时该怎么算） |
| ④ | **主题同步与滚动同步的通信方式** | `PostWebMessageAsJson` / `AddScriptToExecuteOnDocumentCreated` 的用法、往返延迟、滚动同步的消息频率上限（滚动时每帧发一条是否可行，还是必须节流），以及消息协议的草案 |

### 3. 顺带必须确认的事实

- **不联网**：用 `SetVirtualHostNameToFolderMapping` 把本地资源映射成虚拟域名，确认加载本地图片不走网络；验证能否按 `UX_SPEC` §4.3 默认阻止远程资源并统计被阻止的数量；确认禁止脚本执行的做法。
- **运行时缺失**：本机没有 WebView2 运行时时的失败表现与可检测性（`UX_SPEC` §6.4 要求降级为源码打开并提示，**不自动下载**）。
- **实例回收**：创建 → 销毁 → 再创建是否干净（对应 `rove.markdown.webviewIdleTimeout`，默认 300 秒）。
- **DPI 与多显示器**：PerMonitorV2 下跨显示器拖动时 webview 的缩放与位置。
- **占位状态**：WebView2 就绪前先显示骨架（`UX_SPEC` §4.3 性能约定）在时序上是否可行。

### 4. 报告 `docs/M0_WEBVIEW_SPIKE_REPORT.md`

格式参照 `docs/M0_UI_SPIKE_REPORT.md`：结论摘要、验证方法与环境、指标表、分项分析、风险、**明确的 go / no-go**、未验证事项的诚实清单。另外必须包含**推荐的集成设计**，让 R29（Markdown 预览） 可以照着实现：谁拥有 HWND、层级与 z-order 规则、弹出层与预览区重叠时的处理策略、消息协议、生命周期与回收时机。

如果结论是 no-go，报告中给出备选方案的代价评估（原生渲染 `pulldown-cmark`，即 D5 之前的方案，意味着放弃内嵌 HTML、Mermaid 与数学公式），并指出这需要回到 `FEATURES` §12 重新决策 D5。

## 不包含

- Markdown 预览功能本身、`markdown.css` / `highlight.css` 的接入、Mermaid 与 KaTeX 打包（全部在 R29（Markdown 预览））。
- 产品代码与接口改动。

## 验收标准

- [ ] `spikes/webview-gpui/` 可以构建运行，并且在 workspace 之外（不影响 `cargo build --workspace`）
- [ ] 四项验证各有实测数据与截图或录屏，遮挡项必须有"重叠时"的截图
- [ ] 遮挡问题给出至少一个实测可行的规避方案，并说明它对 R16（工作台）、R24（快速打开与命令面板） 的影响面
- [ ] 焦点路由给出一张"按键 → 谁处理"的对照表
- [ ] 首开耗时与内存有冷/热各 3 次以上的测量，并与 400 ms / 60 MB 预算对照
- [ ] 主题与滚动同步给出消息协议草案和实测延迟
- [ ] 无 WebView2 运行时、远程资源阻止、实例回收三项各有结论
- [ ] `docs/M0_WEBVIEW_SPIKE_REPORT.md` 完成，含 go/no-go 与集成设计；`PLAN.md` 阶段 0.2a 状态更新

## 风险与提示

- 遮挡是这次验证最可能卡住的一项。如果结论是"弹出层必须改为独立顶层窗口"，影响的是整个工作台的弹出层实现方式，**必须在 R16（工作台） 开工前把结论交出去**，否则返工面很大。
- 不要为了让 demo 好看而把规避方案做得很复杂。这次要的是"哪条路走得通、代价是什么"，不是一个能用的预览。
- 诚实记录未验证项。M0 两份报告都有"未验证事项"一节，这份也要有。
