## 背景

`FEATURES.md` §3 对链接检测的判定是**照搬**、P1，说明里有一句不能漏掉的话：**打开外部链接前需要确认**。这和立项文档「Rove 不主动发起网络请求」是同一个立场——Rove 自己不联网，但它可以把一个 URL 交给系统浏览器，交出去之前必须让用户点头。

对 Unity 项目来说，这个功能最常用的其实不是 URL 而是**文件路径**：报错日志、`Editor.log`、注释里的 `Assets/Scripts/Player.cs:41`。所以本 issue 的两种链接同样重要：URL 用系统浏览器打开（需确认），文件路径经 R17（编辑器组与标签） 的打开文档服务打开并定位到行。

检测与绘制都在 R19（代码视图 Element） 的代码视图内部完成（R19（代码视图 Element） 的「不包含」里已经点名链接检测归本 issue），用它的装饰、命中测试与视口接口。

必读：`FEATURES.md` §3（链接检测一行）、§10、§13，`UX_SPEC.md` §3.1、§3.3（超长行截断）、§6.1（反馈分级），`docs/compat/SETTINGS.md`（`editor.links`、`editor.multiCursorModifier`，以及「工作台」不支持段中的 `workbench.externalBrowser`、`workbench.externalUriOpeners`、`workbench.trustedDomains.promptInTrustedWorkspace`），`THEME_COLORS.md`（`editorLink.activeForeground`）。

## 目标

### 1. 检测

- `editor.links`（默认 true）为真时，在编辑器文本中检测两类链接：
  - **URL**：`http://`、`https://`、`file://`，以及 `www.` 开头的常见写法（照搬 VS Code 的链接计算规则，包括尾部标点的剥离——`见 https://example.com/a.` 末尾的句号不属于链接）。
  - **文件路径**：绝对路径与相对工作区根的相对路径，支持 `:行号`、`:行号:列号`、`(行号,列号)` 三种位置后缀（Unity 与编译器日志里的常见形式）。路径存在性在检测阶段**不做磁盘访问**，只在打开时校验。
- **按视口惰性检测**：只对可见行加上下预留的若干行做检测，结果**按行缓存**，行内容变化时才失效。绝不每帧重算，也绝不全文扫描（`PROJECT_CHARTER.md` §6 的 1 ms 每帧预算）。
- 遵循 `editor.stopRenderingLineAfter`（默认 10000）：截断点之后不检测（`UX_SPEC.md` §3.3）。
- 检测在后台执行器上完成，结果以 R19（代码视图 Element） 的行内样式区间提交。

### 2. 呈现

- 按住修饰键悬停在链接上时显示下划线，颜色 `editorLink.activeForeground`；修饰键跟随 `editor.multiCursorModifier`（默认 `alt`，此时打开链接的手势是 `Ctrl`，与 VS Code 的说明一致——该设置会同时调整「转到定义」与「打开链接」的手势）。
- 鼠标指针在链接上变为手形；悬停提示显示目标（URL 原文，或路径 + 行号）与一行操作说明，走 R40（C# 导航交互） 已有的悬停卡片通道，**不自己造浮层**。
- `Ctrl+悬停`的下划线判定与 R40（C# 导航交互） 的定义链接共用同一处命中逻辑：同一位置既是标识符又是链接时，**定义优先**（照搬 VS Code），避免两条下划线叠加。

### 3. 打开

- `Ctrl+点击`以及命令 `editor.action.openLink`（VS Code 中没有默认键位，**不要自行分配**）：
  - **文件路径** → 经 R17（编辑器组与标签） 的打开文档服务打开并定位到 `:行号`（`.md` 按 `UX_SPEC.md` §4.3「从跳转中打开」的语义打开源码并定位）；路径不存在时按 `UX_SPEC.md` §6.1 第 2 级在**光标处**提示「未找到文件 `X`」，不打开空标签、不弹通知。
  - **URL** → **先确认，再交给系统默认浏览器**（`FEATURES.md` §3）。确认框中完整显示目标 URL，按钮为「打开」「取消」，并提供「复制链接」。确认后由操作系统的默认程序打开，Rove 自身不发起任何请求。
- 不支持 `workbench.externalBrowser`（指定浏览器）、`workbench.externalUriOpeners`（自定义打开方式）、`workbench.trustedDomains.promptInTrustedWorkspace`（受信域名白名单）——`SETTINGS.md` 中均已判为不支持，因此**每一次打开外部链接都确认**，不记忆域名。这一条要写进 `docs/ARCHITECTURE.md` 的对照表。
- 右键菜单项「打开链接」「复制链接地址」，通过 R01（【接口先行 A1】架构与接口契约） 的登记机制加入。

### 3.1 Markdown 源码中的链接（FEATURES §9）

在 `.md` 源码中识别 Markdown 链接语法 `[文字](目标)`、`<目标>` 与引用式链接：相对路径的 `.md` 目标按 UX_SPEC §4.3“从跳转中打开”的语义打开源码；带 `#标题` 锚点时定位到对应标题（标题位置取自 R26（大纲） 的 Markdown 符号）。链接路径补全属于补全功能，Rove 不做（FEATURES §4）。

### 4. 按级别关闭与性能预算

- `UX_SPEC.md` §3.1 的表里没有列链接检测，但它与同名高亮同属「按行扫描文本」的一类：**超大文件级别关闭**（只读、无语法高亮，检测也无意义），大文件级别**保留**但只对可见行检测。关闭原因登记到 R20（代码视图） 的「当前关闭了哪些功能」接口，供 R22（超大文件与超长行的界面） 的状态栏悬停提示使用。
- 预算：连续滚动时链接检测带来的每帧额外 CPU **< 50 µs**（缓存命中）；单行检测的最坏情况（10000 字符、含大量候选）要给出数字。

### 5. 登记与替换

新增命令、设置项、颜色键、界面字符串、菜单项通过 R01（【接口先行 A1】架构与接口契约） 的登记机制加入，不得写死。装饰、命中测试、视口事件一律经 R19（代码视图 Element） 的接口，打开文件一律经打开文档服务，确认框走 R16（工作台） 的反馈接口。不得在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口。GPUI 类型只出现在 `rove-ui` / `rove-app`。

## 不包含

- Markdown **预览**中的链接（相对 `.md` 链接在预览中打开、外部链接用浏览器打开）：R29（Markdown 预览）。Markdown **源码**中的链接走本 issue 的通用检测。
- 终端、输出、通知、欢迎页中的链接（`FEATURES.md` §10 不做终端与输出；通知里的链接属于 R16（工作台），用 `notificationLink.foreground`）。
- `Ctrl+悬停`的定义预览与下划线本体（R40（C# 导航交互））；悬停卡片框架（R40（C# 导航交互））。
- 超长行的截断标记与「在临时标签中查看这一行」（R22（超大文件与超长行的界面））。
- 指定浏览器、自定义 URI 打开方式、受信域名白名单（见目标第 3 节）。
- 工作区信任（`FEATURES.md` §6 明确不做：Rove 不执行任何代码）。

## 风险与提示

- **确认框的级别有一处规格张力需要在 PR 中说明**：`UX_SPEC.md` §6.1 规定第 5 级模态对话框「只用于不立即处理就会丢失数据的情况」，而 VS Code 打开外部链接用的正是模态确认。按 §0.1 的基线（没写到的地方与 VS Code 一致）与 `FEATURES.md` §3 的「需要确认」，本 issue 采用**模态确认**；如果评审认为应当降级为提示条或通知，要同步修订 §6.1 的措辞，而不是两边各写一套。
- 不要把检测做成全文扫描。一个 1 MB 的日志文件里可能有上万个候选，只要按视口 + 按行缓存就几乎零成本，一旦全文扫描就会在打开文件时卡一下。
- 尾部标点剥离、括号配对（`(见 https://a.com/b(c))`）这类细节是 VS Code 链接计算里真正花心思的部分。先照着 VS Code 的行为造一组用例，再写实现，不要凭直觉。
- 文件路径检测要避免把普通文本误判成路径（`A/B` 这种两个字母夹斜杠的写法到处都是）。建议要求至少包含一个已知扩展名或以 `./`、`../`、盘符、`/` 开头，并把规则写成数据便于调。
- 「定义优先」这条规则要和 R40（C# 导航交互） 一起验证。两个 issue 都在同一个修饰键手势上挂行为，分开测很容易各自通过、合起来打架。
