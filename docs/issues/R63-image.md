## 背景

`FEATURES.md` §6 把图片预览判定为照搬、P1：png、jpg、gif、svg、tga，只读。Unity 工程里图片很多（贴图、图集、UI 素材），点开一张图不应该得到「此文件是二进制文件」的提示——`UX_SPEC.md` §3.5 已经写明：**图片文件直接用图片预览打开**。

实现方式是向 R17（编辑器组与标签） 的编辑器类型登记表注册一个新的编辑器类型（R17（编辑器组与标签） 明确把「图片预览由 R63（图片预览） 登记」留给本 issue），文件到类型的解析沿用 `workbench.editorAssociations`，不在打开路径上写死扩展名分支。

这是 M4 里最小的一个 issue（难度 1），但有一条硬约束：**渲染过程中不得发起任何网络请求**（`PROJECT_CHARTER.md` §2），SVG 尤其容易通过外部引用把网络拉进来。

必读：`FEATURES.md` §6（图片预览一行）、§10；`UX_SPEC.md` §3.5（二进制文件与图片）、§6.2（加载与进度）、§6.4（无法打开文件的错误占位页）；`docs/compat/SETTINGS.md`「图片预览」一节（`mediaPreview.*`）；`THEME_COLORS.md`（`editor.background`、`statusBarItem.*`）。

## 目标

### 1. 图片编辑器类型

- 通过 R17（编辑器组与标签） 的编辑器类型登记机制注册 `vscode.imagePreview`（沿用 VS Code 的编辑器 ID，使共用设置里的 `workbench.editorAssociations` 原样生效），关联 `.png`、`.jpg` / `.jpeg`、`.gif`、`.svg`、`.tga`。
- 从文件树、快速打开、搜索结果、`explorer.openToSide` 打开时走同一条路径；预览标签 / 正式标签的语义由 R17（编辑器组与标签） 决定，本 issue 不另做。
- 标签与编辑器标题显示锁形图标（只读来源与 `UX_SPEC.md` §3.4 一致）；尝试输入时不弹任何东西（没有文本输入目标）。

### 2. 解码与渲染

- 解码在后台执行器上完成，界面线程只做绘制（`ARCHITECTURE.md` 的线程模型）。png / jpg / gif / tga 用纯 Rust 解码器；**不接受任何会读取网络的解码路径**。
- 透明区域画棋盘格（与 VS Code 一致），背景用 `editor.background`。
- GIF：按帧延时播放动画，标签不可见时暂停解码与重绘（避免后台占 CPU，`PROJECT_CHARTER.md` §6 的每帧 CPU 预算）。
- 超出显示能力的图片（例如 16384 px 以上或解码后超过数百 MB）不尝试整图解码，显示 §6.4 的错误占位页，说明一句话原因。
- 解码失败、文件截断、扩展名与实际格式不符时同样走错误占位页，带「重试」「在资源管理器中显示」。

### 3. SVG：离线渲染

- 用 `usvg` / `resvg` 这类纯 Rust 栈栅格化，**显式关闭一切外部加载**：`xlink:href` / `href` 指向 `http(s)://` 的图像一律不加载；字体只使用本机已安装字体与内置回退，不下载 Web 字体；`<script>` 不执行（栅格化器本来就不执行脚本，但要有测试断言）。
- 被阻止的外部资源用 `UX_SPEC.md` §6.1 第 3 级提示条告知「已阻止 N 个远程资源」，与 R29（Markdown 预览） 的措辞保持一致。
- SVG 按当前缩放倍率重新栅格化，而不是把首次栅格化的位图放大。

### 4. 缩放与适应窗口

照搬 VS Code 的图片预览交互：

- 默认「适应窗口」；图片小于视口时按 1:1 显示，不放大。
- 点击放大一档、`alt+点击` 缩小一档、`ctrl+滚轮` 连续缩放、拖动平移；缩放档位与 VS Code 一致（`0.1×` 到 `20×`）。
- 状态栏右侧登记两个条目（通过 R16（工作台） 的状态栏登记机制，`when` 限定为图片编辑器活动）：**尺寸**（`1920×1080`，点击无动作）与**缩放倍率**（点击在「适应窗口」与 `100%` 之间切换），顺序与 VS Code 一致。
- 文件在外部被覆盖（Unity 重新导入贴图）时自动重新解码并**保持当前缩放与平移位置**。

### 5. 登记与替换

新增编辑器类型、状态栏条目、界面字符串、颜色键的使用全部通过 R01（【接口先行 A1】架构与接口契约） 与 R16（工作台） 的登记机制加入，不得写死。`mediaPreview.video.autoPlay`、`mediaPreview.video.loop` 是 `SETTINGS.md` 中仅有的两个 `mediaPreview.*` 条目，而 Rove 不做视频预览：本 issue **只登记不生效**（登记是为了共用设置文件里的这两项不被当成未知键），并在 PR 中说明。R02（【接口先行 A2】行走骨架） 中没有本 issue 对应的 `SKELETON(...)` 标记，只在 `docs/ARCHITECTURE.md` 中新增自己的一行。不得在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口。

## 不包含

- 视频与音频预览（`FEATURES.md` §6 只列了五种图片格式）。
- 图片编辑、裁剪、另存为、复制为 PNG。
- 把图片当文本打开的入口（`explorer.openWith` 属于 R17（编辑器组与标签） 的编辑器类型解析）；二进制文件的「仍然打开」提示（R07（文本缓冲） / R17（编辑器组与标签））。
- Unity 专有格式（`.psd`、`.exr`、`.dds`、图集）的解码；在 PR 中记录这个决定，以后按需再提 issue。
- 图片在 Markdown 预览中的显示（R29（Markdown 预览），走 WebView2）。

## 风险与提示

- **解码库会带进依赖**。R73（精简 GPUI 的网络依赖） 正在把 gpui 的 HTTP/TLS 栈拆掉，本 issue 如果引入一个顺手带 `reqwest` 的 SVG / 字体库，就会把那笔工作抵消掉。选依赖时先看 `cargo tree`，并在 PR 中附上新增包数。
- gpui 自带的图片加载能力可以用，但要确认它不走网络路径；用不了就自己解码，不要为了省事打开 gpui 的 `http_client`。
- 动画 gif 与「每帧 CPU < 1 ms」的预算有冲突风险：一张 1000 帧的大图足以吃满一个核。按帧延时调度，不要每帧全图重新解码。
- TGA 在 Unity 工程里常见但解码器支持参差（RLE 压缩、上下翻转的原点），准备几个真实样例再选库。
