# R13 设置层：与 VS Code 共用 settings.json（JSONC、语言级覆盖、热加载、保留格式写入、默认值差异规则）

| 里程碑 | 难度 | 领域 | 并行批次 | 前置依赖 | 被依赖 |
|---|---|---|---|---|---|
| M1 只读阅读器 | 3 困难 | core | 第 2 批 | R01（【接口先行 A1】架构与接口契约） | R28（欢迎页、最近打开、启动参数打开，以及首选项入口）、R29（Markdown 预览）、R31（【集成验收】M1）、R70（图形化设置界面）、R76（自动更新） |

> 认领前请阅读 `AGENTS.md`、`docs/ARCHITECTURE.md`（R01 完成后）与 `docs/issues/README.md`。前置依赖全部合并后才能开工。

## 背景

D4 决定 Rove **与 VS Code 共用同一份 `settings.json`**，落地规则写在 `FEATURES` §13 的 7 条里。这份文件是用户的真实配置，Rove 读它、偶尔写它，出错的代价很高（丢注释、改坏格式、把 Rove 的默认值写进去污染 VS Code）。本 issue 把这 7 条规则完整实现出来。

支持的设置项清单是 `docs/compat/SETTINGS.md`（由 `scripts/compat/gen_compat_docs.py` 生成，判定规则在 `scripts/compat/rules.py`）。实现放在 `rove-config`，在 R01（【接口先行 A1】架构与接口契约） 定义的设置读取与设置项登记接口背后；本 PR 不修改这些接口。

## 目标

### 1. 文件位置（规则 1）

默认 `%APPDATA%\Code\User\settings.json`。改为其他发行版的目录（VSCodium、Cursor）时，使用启动参数 `--vscode-user-dir`（优先）或环境变量 `ROVE_VSCODE_USER_DIR`（FEATURES §13 规则 1）。这个位置**不能**写在设置文件里，所以没有对应的 `rove.*` 设置项。本机没有安装 VS Code 时，在同样的位置创建文件。

### 2. 读取（规则 2）

- 解析 **JSONC**：行注释、块注释、尾逗号、重复键（后者胜出，与 VS Code 一致）；
- 语言级覆盖：`"[csharp]": { ... }`，按 `SETTINGS.md` §5"语言级覆盖"一节支持的 32 项；
- **Rove 不支持的设置项静默忽略**，不报错、不提示（同一个文件里本来就有大量 VS Code 专有项）。

### 3. 设置项登记（规则 2、4）

按 `SETTINGS.md` 登记键名、类型、VS Code 默认值、以及"Rove 是否生效"。M1 必须覆盖"支持 P0"的 375 项；P1 / P2 可以只登记不生效。`rove.*` 专有项按 `SETTINGS.md` §4 登记（`rove.largeFile.threshold`、`rove.files.extraExclude`、`rove.files.extraReadonlyInclude`、`rove.index.*`、`rove.markdown.*`、`rove.contextBasket.*`、`rove.metadataView.showDocs`）。

**全部通过 R01（【接口先行 A1】架构与接口契约） 的设置项登记机制注册**，使用处不允许写死键名、默认值或类型。提供强类型读取（支持语言级覆盖），读到类型不匹配的值时回落到默认值并记录一条可定位的警告。

### 4. Rove 的默认值差异（规则 5）

`SETTINGS.md` §3 的四条，**只在用户没有设置该项时生效，并且永远不写入共用文件**：

| 设置项 | VS Code 默认值 | Rove 默认值 |
|---|---|---|
| `files.autoGuessEncoding` | `false` | `true` |
| `files.candidateGuessEncodings` | `[]` | `["gbk"]` |
| `workbench.editorAssociations` | `{}` | `{"*.md": "vscode.markdown.preview.editor"}` |
| `search.useIgnoreFiles` | `true` | 整体忽略（Rove 不读 `.gitignore`） |

登记机制要能表达"VS Code 默认值"和"Rove 默认值"两个值，并提供"该项是否由用户显式设置"的查询——R07（文本缓冲）、R29（Markdown 预览）、R25（全局搜索） 都需要它。

### 5. 写入（规则 3）

只有用户在 Rove 中主动修改设置时才写（切换主题、改字号等）。要求：

- **保留原有的注释、格式和键的顺序，只修改目标键**。必须用 JSONC 的区间编辑（像 VS Code 的 `jsonc-parser` 那样定位到该键的值并替换字节区间），**不允许"反序列化 → 序列化"整份重写**；
- 写入前备份到 `%LOCALAPPDATA%\Rove\settings-backup\`（带时间戳，保留最近 N 份）；
- 原子写入（临时文件 + 重命名），文件被占用时重试；
- 新增键时插入位置与缩进风格跟随文件现有风格。

### 6. 热加载（规则 6）

监听 `settings.json`（以及同目录的 `keybindings.json`，由 R14（键位与命令层） 消费）。VS Code 改了设置，Rove 实时生效，反之亦然。要处理：编辑器的"写临时文件再重命名"模式、短时间内多次触发（去抖）、自己写入时不要把自己的写触发成一次重载。

文件有语法错误时**继续使用上一次有效的设置**（`UX_SPEC` §6.4），并对外报出错误位置（状态栏警告图标与问题面板由 R16（工作台） 实现）。

## 不包含

- `keybindings.json` 的解析与键表达式（R14（键位与命令层））。
- 图形化设置界面（R70（图形化设置界面））、首次打开共用文件时的提示条与齿轮菜单（R28（欢迎页、最近打开、启动参数打开，以及首选项入口））。
- 状态栏警告图标、问题面板（R16（工作台））。
- 工作区级设置（`.vscode/settings.json`）：首版不做，在 PR 中记录这个决定。

## 验收标准

- [ ] JSONC 解析有单元测试：行注释、块注释、尾逗号、重复键、BOM、CRLF
- [ ] 语言级覆盖有测试，含"语言级覆盖 > 全局 > Rove 默认值 > VS Code 默认值"的优先级
- [ ] **保留格式写入**有往返测试：修改一个键后，文件中除该键的值以外**字节完全不变**（注释、空行、键顺序、缩进风格）
- [ ] 写入前生成备份文件；原子写入与占用重试有测试
- [ ] 热加载双向测试：外部修改文件后 Rove 生效；Rove 写入后不触发自激重载
- [ ] 语法错误时沿用上一份有效设置，并给出带行列的错误信息
- [ ] Rove 默认值的四条：未设置时生效、用户设置后让位、且写入文件后文件中不出现这些默认值——各有测试
- [ ] `SETTINGS.md` 中"支持 P0"的条目全部完成登记，并有一个对照该文档的测试防止漏项
- [ ] 不支持的键被静默忽略，且不产生任何用户可见提示
- [ ] 新增集成测试覆盖"读设置 → 改一个键 → 写回 → 热加载"；R02（【接口先行 A2】行走骨架） 的端到端测试继续通过
- [ ] `cargo tree -p rove-config -i gpui` 为空

## 风险与提示

- **写入是本 issue 风险最高的部分**。共用文件里通常有大量用户手写的注释和分组，一次"反序列化 → 序列化"就会全部丢掉。先写往返测试再写实现。
- 备份目录会无限增长，要有上限（例如保留 20 份）；备份失败时**不要**继续写入。
- 热加载和写入会互相触发。实现时记录"自己最近一次写入的内容哈希"，收到变更事件时先比对再决定是否重载。
- `SETTINGS.md` 是生成的文档。发现判定不合理时改 `scripts/compat/rules.py` 并重新生成，**不要手改文档**，也不要在代码里偷偷支持一个文档上写着"不支持"的键。
