> 认领前请阅读 `AGENTS.md`、`docs/ARCHITECTURE.md`（R01 完成后）与 `docs/issues/README.md`。前置依赖全部合并后才能开工。

## 背景

“**任何大小的文本文件都能秒开**”是 Rove 相对 VS Code 最直观的差异（`UX_SPEC.md` §3.1）。R08（文件大小分级与超大文件） 提供了内存映射、分块行索引与增量索引，R19（代码视图 Element） 提供了 f64 滚动模型，但用户看到的那一层——提示条、状态栏标记、索引进度、转到行的等待、流式查找、超长行的截断标记——还没有人做。本 issue 补齐这一层。

M0 已实测：1 GB 文件 `Doc::open` 恒定在 1 ms 量级，首屏在首帧即可绘制；全量行索引热缓存 0.58–0.86 s、冷缓存约 3.1–3.3 s（`M0_UI_SPIKE_REPORT.md` §4.3）。所以交互设计的前提是“首屏立即可见、索引在后台补全”，而不是“先等索引”。

必读：`UX_SPEC.md` §3.1、§3.2、§3.3、§6.1、§6.2，`M0_UI_SPIKE_REPORT.md` §4.3、§8（第 10 条：超长行未验证），`SETTINGS.md`（`rove.largeFile.threshold`、`editor.largeFileOptimizations`、`editor.stopRenderingLineAfter`），`docs/compat/KEYBINDINGS.md`（Rove 专有命令 `rove.editor.openLongLine`）。

## 目标

### 1. 超大文件的提示条与状态栏（UX_SPEC §3.2）

- **不弹通知**。打开时在编辑器顶部显示一条可关闭的提示条（`UX_SPEC.md` §6.1 第 3 级，复用 R16（工作台） 的提示条组件）：“超大文件（1.2 GB）：只读，已关闭语法高亮等功能。”体积按实际大小格式化。
- 状态栏右侧的 `超大文件 · 只读`：条目由 R27（状态栏条目） 登记（与只读标记是同一个条目的不同状态），本 issue 只提供超大文件状态下的数据；悬停提示列出被关闭的功能，内容来自 R20（代码视图） 的“当前关闭了哪些功能”查询接口。
- 大文件级别（≥ 20 MB 或 ≥ 30 万行）**不显示提示条**，只在状态栏标记；`editor.largeFileOptimizations` 为 false 时不启用这一级。

### 2. 行索引进度（UX_SPEC §3.2）

- 首屏立即显示；尚未索引的部分仍可滚动，**滚动条按字节位置计算**，索引推进时平滑过渡到按行计算，不得出现滚动位置跳变。
- 状态栏显示 `行索引 45%`，完成后该条目消失。属于“正常的后台工作”，**永不弹通知**（§6.1）。
- 文件在外部被修改：重新映射并保持滚动位置；若只是在末尾追加（日志场景），只增量更新索引并保持滚动位置与进度显示（增量索引由 R08（文件大小分级与超大文件） 提供）。

### 3. 转到行的等待（UX_SPEC §3.2）

`workbench.action.gotoLine`（`ctrl+g`，界面在 R24（快速打开与命令面板））输入的目标行若已索引则直接跳转；**尚未索引时在输入框下方提示“正在建立行索引，完成后跳转”，索引到达该行后自动跳转**。等待期间可取消（§6.2：可能超过 1 秒的操作必须可取消）。本 issue 提供这一等待状态与回调，R24（快速打开与命令面板） 负责在快速输入框中展示。

### 4. 流式查找（UX_SPEC §3.2）

- 在超大文件上，`ctrl+f` 的查找在后台以流式方式进行：R21（当前文件查找条） 的匹配计数位置显示“已找到 N 处 · 已搜索 37%”，结果逐步出现，可以随时在已找到的结果之间跳转，可以取消。
- **替换按钮隐藏**（M1 本来就没有替换，M3 的 R47（当前文件替换） 也不得在超大文件上出现）。
- 查找装饰仍然只为可见行生成，不得一次性生成全部匹配的装饰。

### 5. 超长行（UX_SPEC §3.3）

- 单行超过 `editor.stopRenderingLineAfter`（VS Code 默认 10000 字符）时超出部分不渲染，**沿用该设置**；行尾显示灰色标记“…（已截断，共 N 个字符）”。
- 点击标记或执行 `rove.editor.openLongLine`（Rove 专有命令，无默认键位）：在一个**只读的临时标签**中打开这一行，并开启软换行。临时标签通过 R17（编辑器组与标签） 的打开文档服务创建（一个只读的内存文档）；软换行在 R57（软换行） 合并前先按固定宽度断行显示，并在 PR 中注明这一临时实现。
- 标记与装饰走 R19（代码视图 Element） 的行内覆盖物接口；颜色只用 `THEME_COLORS.md` 中已支持的键（如 `descriptionForeground`、`editorLineNumber.foreground`），**不新造颜色键**。
- 压缩过的 JSON（整个文件只有一行）走同一条路径；“格式化后查看”是 R66（跟随文件末尾、格式化后查看） 的范围，本 issue 不做。

### 6. 登记与替换

新增命令（`rove.editor.openLongLine`）、设置项的读取、颜色键的使用、界面字符串、状态栏条目全部通过 R01（【接口先行 A1】架构与接口契约） 的登记机制加入，不得写死。R02（【接口先行 A2】行走骨架） 中没有本 issue 对应的 `SKELETON(...)` 标记，本 issue 只在 `docs/ARCHITECTURE.md` 中新增 / 更新自己的一行。不得在本 PR 中修改 R01（【接口先行 A1】架构与接口契约） 的接口。GPUI 类型只出现在 `rove-ui` / `rove-app`。

## 不包含

- 内存映射、分块行索引、增量索引、文件大小分级的判定（R08（文件大小分级与超大文件））；文档级别的解析与临时标签的创建机制（R17（编辑器组与标签））。
- **跟随文件末尾**（`rove.editor.followTail`）与**格式化后查看**（`rove.editor.viewFormatted`）：都属于 R66（跟随文件末尾、格式化后查看）（M4），本 issue 不做，也不预留界面元素。
- 按级别关闭高亮、折叠等功能的实现（R20（代码视图））；只读提示与锁形图标（R20（代码视图））。
- 软换行（R57（软换行））、缩略图（R55（缩略图与概览标尺））。
- 全局搜索对大文件的处理（R25（全局搜索））。

## 验收标准

测量用 R04（性能基准与预算守护） 的测试数据（1 GB 的 `big1g.txt` 式文件、单行 50 MB 的压缩 JSON），原始数据附在 PR 中：

- [ ] 打开 1 GB 文件：**不弹任何通知**；首屏可见在进程启动后 < 1 s（`PROJECT_CHARTER.md` §6）；顶部提示条文案与 §3.2 一致且可关闭、可“不再提示”
- [ ] 状态栏显示 `超大文件 · 只读`，悬停列出被关闭的功能；索引期间显示 `行索引 N%` 并在完成后消失
- [ ] 索引未完成时向下滚动到未索引区域不崩溃、不卡顿；索引完成后滚动条位置与行号一致，期间没有可见的位置跳变
- [ ] `ctrl+g` 跳到已索引的行立即生效；跳到未索引的行时显示等待提示并在索引到达后自动跳转；等待中可取消
- [ ] 1 GB 文件上 `ctrl+f` 查找：显示“已找到 N 处 · 已搜索 X%”，可在已有结果间跳转，可取消；替换按钮不存在
- [ ] 单行 50 MB 的压缩 JSON：打开不卡死，行尾显示“…（已截断，共 N 个字符）”且字符数正确；点击后在只读临时标签中打开该行并断行显示
- [ ] `editor.stopRenderingLineAfter` 改为其他值后截断位置随之变化
- [ ] 外部在文件末尾追加内容后，滚动位置保持、索引增量更新、进度显示正确
- [ ] 全程遵守 §6.1：没有任何通知，只有提示条与状态栏
- [ ] 超大文件打开期间 R19（代码视图 Element） 的帧预算不退化（复跑滚动基准，附对比数据）
- [ ] R02（【接口先行 A2】行走骨架） 的端到端测试仍然通过；新增“超大文件打开 → 索引进度 → 转到行等待 → 流式查找 → 超长行截断”的集成测试
- [ ] `docs/ARCHITECTURE.md` 已更新

## 风险与提示

- 滚动条从“按字节”切换到“按行”的过渡是最容易出问题的地方。建议在索引推进时持续用同一个映射函数（已索引部分按行、未索引部分按字节线性外推），而不是在完成时一次性切换。
- `editor.stopRenderingLineAfter` 是 VS Code 的隐藏设置，已列入 `SETTINGS.md` 的“Rove 支持的 VS Code 隐藏设置”，默认值 10000。不要另外定义 `rove.*` 替代项。
- 超长行是 M0 的未验证项（§8 第 10 条，原型统一截断到 2048 字节）。真实的 minified JS / 单行 JSON 可能暴露整形、命中测试、选区的新问题；发现 R19（代码视图 Element） 的接口不够用时记录下来，按契约变更流程处理，不要在本 issue 里绕过去。
- 临时标签的生命周期要想清楚：关闭源文件时临时标签怎么办、同一行重复打开是否复用。照搬 VS Code 对临时编辑器的做法（复用同一个标签）。
