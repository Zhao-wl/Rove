## 0. 写法约定

### 0.1 基线
**凡是本文档没有写到的地方，一律与 VS Code（Windows 版、当前稳定版）的行为保持一致**，包括布局、快捷键、菜单结构、交互细节、空状态和错误提示的措辞风格。实现时遇到规格没写到的细节，以 VS Code 的实际表现为准。

### 0.2 差异的记录格式
每一处与 VS Code 不同的地方，都写清楚四件事：**场景、VS Code 的行为、Rove 的行为、原因**。原因必须能追溯到 `FEATURES.md` 中的判定或决策（D1–D4）。

## 1. 工作台

### 1.1 整体布局
与 VS Code 默认布局一致：标题栏、活动栏、主侧边栏、编辑器组网格、面板、状态栏。辅助侧边栏（右侧）是 P2，首版没有。

### 1.2 标题栏与菜单

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 菜单栏 | 文件、编辑、选择、查看、转到、**运行、终端**、帮助 | 文件、编辑、选择、查看、转到、帮助 | 不做调试和终端 |
| 菜单项 | 包含所有已安装功能的菜单项 | 只保留 Rove 已实现的功能；没有实现的菜单项**直接不显示**，而不是置灰 | 避免出现永远点不了的菜单项 |
| 命令中心 | 标题栏中间的搜索框，点击后打开快速打开 | 相同 | 照搬 |
| 布局控制按钮 | 切换主侧边栏、面板、辅助侧边栏，以及自定义布局 | 只保留切换主侧边栏和面板 | 首版没有辅助侧边栏 |
| 账号、Copilot 图标 | 有 | 没有 | 不做账号和内置 AI |

|---|---|---|---|

|---|---|---|---|

## 2. C# 导航

### 2.1 索引状态

索引在后台静默进行，**正常情况下不弹出任何通知**，只在状态栏左侧显示一个状态项。

| 状态 | 状态栏显示 | 悬停提示 | 点击后 |
|---|---|---|---|
| 未安装语义组件 | `$(info) C# 基础导航` | 跳转和引用是近似结果。安装语义组件后可以获得精确结果。 | 打开说明页面，内容包括安装方法 |
| 首次构建中 | `$(sync~spin) C# 索引 37%` | 已处理文件数 / 总数、预计剩余时间；构建期间的结果是近似的 | 显示索引详情（同下面“就绪”状态的详情） |
| 就绪 | `$(check) C#` | 上次构建时间、文件数、符号数、缓存位置和大小 | 显示索引详情，可以执行“重建索引”“打开索引日志” |
| 增量更新中 | `$(sync~spin) C#`（不显示百分比） | 正在更新 N 个文件 | 同“就绪” |
| 失败 | `$(error) C# 索引失败` | 失败原因的一句话摘要 | 显示错误详情、日志和“重试”按钮 |
| 工作区里没有 C# 代码 | 不显示 | — | — |

- 失败时只弹出一次通知（含“查看详情”和“重试”）；同一个原因不会重复弹出。
- 如果没有找到 `.csproj`（例如 Unity 还没有生成项目文件），就根据 `.asmdef` 推断项目结构。此时悬停提示中加一句：“未找到项目文件，正在使用推断的项目结构。在 Unity 中执行 Assets → Open C# Project 可以生成项目文件。”

### 2.2 近似结果

语义索引还没有就绪、语义组件没有安装、或者光标所在的位置被修改过但还没保存时，结果来自快速索引或语法分析，是近似的（见 `LANGUAGE_INTELLIGENCE.md` §3.2）。

| 功能 | 精确结果时 | 近似结果时 |
|---|---|---|
| 转到定义（只有一个候选） | 直接跳转 | 直接跳转，状态栏临时显示一行提示“近似结果：语义索引未就绪”，3 秒后消失 |
| 转到定义（多个候选） | 打开速览窗口（与 VS Code 的 `editor.gotoLocation.multipleDefinitions` 默认值一致） | 打开速览窗口，标题中注明“近似 · N 个候选” |
| 查找引用 | 速览窗口 | 速览窗口，标题中注明“近似”；结果是按名称匹配到的同名符号，可能包含无关项 |
| 悬停 | 签名和文档注释 | 能找到声明时显示签名；底部加一行灰色小字“近似结果” |
| 同名高亮 | 只高亮同一个符号 | 退化为按文本高亮，没有额外提示 |

**原则**：近似结果永远要标明，但标注要克制，不能干扰阅读。精确结果没有任何额外标记。

### 2.3 速览窗口（D3）

外观和交互照搬 VS Code 的 peek 窗口：在当前行下方内嵌展开，左侧是代码预览，右侧是按文件分组的结果列表。

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 打开方式 | `Shift+F12` 查找引用、`Alt+F12` 速览定义、`Ctrl+Shift+F12` 速览实现 | 相同 | 照搬 |
| 左侧代码预览 | 可以直接编辑 | **只读**；双击或按 `Enter` 在编辑器中打开并定位 | 编辑只在主编辑器中局部进行，速览专注于阅读 |
| 结果列表的展开 | 结果较少时展开全部文件 | 结果总数 ≤ 100 时展开全部文件；超过时只展开第一个文件，其余文件折叠，并在文件名旁显示数量 | 大型项目中一个符号可能有几万处引用（M0 实测最多 4.7 万） |
| 标题 | 符号名 + 结果数 | 符号名 + 结果数；近似结果时加“近似”标记（§2.2） | Rove 特有 |
| 结果来自外部符号 | 打开“从元数据”的反编译视图 | 显示元数据视图的片段（第 4 块） | Rove 用预计算的元数据视图 |
| 键盘 | `↑↓` 选择、`Enter` 打开、`Esc` 关闭、`F4` / `Shift+F4` 跳到下一个 / 上一个结果 | 相同 | 照搬 |
| 在速览中继续跳转 | 在预览中可以再按 `F12` | 相同 | 照搬 |

### 2.4 其他导航交互
以下都与 VS Code 一致，这里只列出来以便确认范围：
- 按住 `Ctrl` 悬停时，标识符显示下划线，并弹出定义预览；`Ctrl+点击` 跳转到定义
- `Alt+←` / `Alt+→` 后退、前进；`Ctrl+K Ctrl+Q` 跳到上次编辑的位置
- `Ctrl+Shift+O` 转到文件中的符号，`Ctrl+T` 转到工作区中的符号（P1）

## 3. 文件状态：超大文件、只读、编码与换行符

### 3.1 文件大小分级

VS Code 对大文件的处理是“关闭部分功能”（`editor.largeFileOptimizations`）；文件过大时会提示内存不足，甚至无法打开。Rove 分三级处理，**任何大小的文本文件都能秒开**。

| 级别 | 判定条件 | 可编辑 | 关闭的功能 |
|---|---|---|---|
| 普通 | 其余情况 | 是 | 无 |
| 大文件 | ≥ 20 MB 或 ≥ 30 万行（与 VS Code `editor.largeFileOptimizations` 的阈值一致，该设置为 false 时不启用这一级） | 是 | 缩略图、粘性滚动、括号对着色、同名高亮、语义高亮、基于语法的折叠（保留基于缩进的折叠）。语法高亮在后台完成，完成前先显示纯文本 |
| 超大文件 | ≥ 64 MB（`rove.largeFile.threshold`） | **否，只读** | 上面的全部功能，再加上语法高亮、所有折叠、软换行、替换 |

超大文件采用内存映射，打开时不把整个文件读进内存。之所以只读，是因为要在 GB 级的文件上支持编辑，需要一套完全不同的缓冲结构，超出了“局部编辑”的定位。

### 3.2 超大文件模式的交互

| 场景 | VS Code | Rove |
|---|---|---|
| 打开时 | 弹出通知“由于文件较大，已关闭部分功能”，并提供“强制启用”按钮；文件过大时可能无法打开 | 直接打开，不弹通知。编辑器顶部显示一条可以关闭的提示：“超大文件（1.2 GB）：只读，已关闭语法高亮等功能。”状态栏显示 `超大文件 · 只读`，悬停时列出被关闭的功能 |
| 行索引还没建完时 | — | 首屏立即显示。尚未建立索引的部分仍然可以滚动，滚动条按字节位置计算；状态栏显示 `行索引 45%`。M0 实测 1 GB 文件的全量行索引需要 0.6 s（热缓存）到 3 s（冷缓存） |
| 转到行（`Ctrl+G`） | 正常 | 目标行已经索引：直接跳转；尚未索引：在输入框下方提示“正在建立行索引，完成后跳转”，完成后自动跳转 |
| 当前文件内查找（`Ctrl+F`） | 正常 | 在后台以流式方式查找，查找条中显示“已找到 N 处 · 已搜索 37%”；可以在结果之间跳转；替换按钮隐藏 |
| 尝试输入 | — | 与只读文件一致（见 §3.3） |
| 文件在外部被修改 | 重新加载 | 重新映射并保持滚动位置。如果文件只是在末尾追加了内容（例如日志），就只增量更新索引 |
| 跟随文件末尾（日志） | 没有此功能 | **P1（已确认）**：命令“跟随文件末尾”，文件增长时自动滚动到最后一行，类似 `tail -f`，适合查看 Unity 的 `Editor.log`；用户向上滚动时自动暂停跟随，状态栏显示“已暂停跟随”，点击恢复 |

### 3.3 超长行

| 场景 | VS Code | Rove |
|---|---|---|
| 单行超过 `editor.stopRenderingLineAfter`（默认 10000 个字符） | 超出部分不渲染 | 相同（沿用该设置），行尾显示灰色标记“…（已截断，共 N 个字符）”。点击标记后在一个只读的临时标签中打开这一行，并开启软换行 |
| 压缩过的 JSON（整个文件只有一行） | 同上 | 同上；另外在标记旁边提供“格式化后查看”，在一个新标签中打开格式化后的副本，原文件不动 |

### 3.4 只读状态

**只读的来源**：
1. 超大文件（§3.1）
2. 元数据视图（第 4 块）
3. 磁盘上的只读属性（遵循 VS Code 的 `files.readonlyFromPermissions`）
4. 匹配 VS Code 的 `files.readonlyInclude` / `files.readonlyExclude` 规则
5. **Rove 默认附加规则**：`Library/PackageCache/**` 默认只读。原因是 Unity 会覆盖这个目录，在这里做的修改会丢失。这条规则写在 `rove.files.extraReadonlyInclude` 中，不改写 VS Code 的设置（第 13 节规则 5）

**交互**：与 VS Code 一致。标签和编辑器标题显示锁形图标；尝试输入时在光标处弹出提示“无法在只读编辑器中编辑”，并说明原因（如“Unity 包缓存目录，修改会被覆盖”）。命令“在此会话中切换只读”可以临时取消只读，超大文件除外。

### 3.5 编码

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 打开文件时的编码识别 | 默认**不猜测**（`files.autoGuessEncoding` 默认为 false），所以 GBK 文件会显示为乱码 | 用户没有设置 `files.autoGuessEncoding` 时，Rove **默认开启自动识别**，候选编码默认为 GBK（`files.candidateGuessEncodings`）。用户显式设置了该项时，遵从用户的设置 | Unity 项目中常有 GBK 编码的中文注释；Rove 的默认值只在用户未设置时生效（D4 第 13 节规则 5） |
| 状态栏的编码项 | 显示编码，点击后可以“通过编码重新打开”或“通过编码保存” | 相同；如果编码是自动识别出来的，悬停提示中注明“自动识别” | 照搬 |
| 带 BOM | 保留 | 保留 | 照搬 |
| 保存时有无法编码的字符（例如在 GBK 文件中输入了 emoji） | 静默替换为 `?` | **保存前提示**：“有 3 个字符无法用 GBK 保存。”提供三个选项：“改用 UTF-8 保存”“仍然保存（替换为 ?）”“取消” | 避免静默丢失数据 |
| 二进制文件 | 提示“此文件是二进制文件或使用了不支持的文本编码”，并提供“仍然打开” | 相同；图片文件直接用图片预览打开 | 照搬 |

### 3.6 换行符

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 状态栏的换行符项 | 显示 LF / CRLF，点击后可以切换 | 相同 | 照搬 |
| 混合换行符的文件 | 打开时**静默统一**为占多数的那种换行符，保存后整个文件都会改变 | **保持原样**：状态栏显示 `混合`，点击后可以选择统一为 LF 或 CRLF；新输入的换行使用占多数的那种 | 不让“看一眼、保存一下”就产生整文件的差异，这对 AI 工具和版本控制都很重要 |
| 新建文件 | 使用 `files.eol`（Windows 上 auto 即 CRLF） | 相同 | 照搬 |
| 异常行终止符（LS、PS 等） | 提示是否移除 | 相同（P2） | 照搬 |

## 4. 特殊视图：元数据视图、结构树、Markdown 预览

### 4.1 元数据视图（外部符号）

跳转到 DLL 中的符号时（例如 `UnityEngine.Transform`、`System.Collections.Generic.List<T>`），Rove 打开一个由索引预先生成的只读视图（见 `LANGUAGE_INTELLIGENCE.md`）。

| 场景 | VS Code（C# Dev Kit） | Rove | 原因 |
|---|---|---|---|
| 内容 | 反编译出的完整源码，或者“从元数据”生成的签名 | **只有签名和 XML 文档注释，没有方法体**，不做反编译 | 索引预先生成，体积可控；阅读 API 时签名和文档已经足够 |
| 标签标题 | `Transform [从元数据]` | `Transform [元数据]`，带锁形图标 | 只读（§3.4） |
| 文件头 | `#region 程序集 UnityEngine.CoreModule, Version=…` 加 DLL 路径 | 相同：程序集名、版本、DLL 完整路径，放在一个默认展开的 `#region` 里 | 照搬 |
| 面包屑 | — | `UnityEngine.CoreModule › UnityEngine › Transform › position` | 与源码文件的面包屑行为一致 |
| 文档注释 | 以 `///` 注释的形式显示 | 相同；`rove.metadataView.showDocs` 设为 false 时隐藏 | 照搬 |
| 在元数据视图里继续跳转 | 可以 | 可以：`F12` 跳到其他类型（源码或元数据），`Alt+F12` 速览 | 照搬 |
| **在元数据视图里查找引用** | 只能在 C# Dev Kit 加载的解决方案范围内查找 | `Shift+F12` 列出**工作区中所有使用这个 API 的位置**（来自预计算索引），例如“项目里哪些地方用了 `Transform.position`” | Rove 的增强，直接得益于预计算索引 |
| 标签复用 | 同一个类型只开一个标签 | 相同；跳到同一类型的其他成员时只滚动定位 | 照搬 |
| 嵌套类型 | 打开外层类型，并定位到嵌套类型 | 相同 | 照搬 |
| 找不到元数据（组件未安装，或索引中没有这个符号） | — | 状态栏临时提示“未找到 `Xxx` 的元数据”，不打开空标签 | 避免出现空白页 |

### 4.2 JSON/YAML/XML 结构树

**结构树放在资源管理器中的“大纲”小节**，而不是新增一个视图。VS Code 本身就会在大纲中显示 JSON 的键，Rove 把同样的做法扩展到 YAML 和 XML，并补充值预览。

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 支持的类型 | JSON（显示键名）；YAML、XML 需要安装扩展 | JSON、YAML、XML 都内置支持 | 内置，不依赖扩展 |
| 节点显示 | 键名 + 类型图标 | 键名 + 类型图标 + **值预览**（字符串、数字等显示截断后的值；对象和数组显示子项数量，如 `items [24]`）。XML 节点显示元素名 + 关键属性（`id`、`name`）+ 子元素数量 | 不展开也能看清结构 |
| 与光标联动 | `outline.followCursor` | 相同 | 照搬 |
| 点击节点 | 跳转到源码 | 相同 | 照搬 |
| 过滤 | 在大纲中直接输入即可过滤 | 相同 | 照搬 |
| 右键菜单 | 有限 | 新增：复制路径（JSON 和 YAML 是 `$.items[3].name` 格式，XML 是 `/root/item[3]` 格式）、复制值、折叠同级节点 | Rove 的增强 |
| 当前位置的路径 | 面包屑 | 面包屑（不另外在状态栏显示路径，避免信息重复） | 照搬 |
| 语法错误 | JSON：波浪线加问题面板 | JSON、YAML、XML 都用波浪线加问题面板；**不做 JSON Schema 校验** | FEATURES §9 |
| 格式化 | `Shift+Alt+F`（JSON 内置，XML 需要扩展） | JSON、XML 都内置；支持“格式化选中内容”；新增命令“压缩 JSON” | FEATURES §4 |
| 大文件与超大文件 | — | 大文件：结构树在后台构建，节点在展开时才加载；超大文件：不提供结构树，大纲中提示原因 | 性能预算 |

**Unity YAML 资产（P2，已确认）**：`.prefab`、`.unity`、`.asset` 由多个以 `--- !u!1 &12345` 开头的文档组成。结构树可以按 Unity 的类型 ID 显示可读名称（`!u!1` 显示为 GameObject，`!u!4` 显示为 Transform，`!u!114` 显示为 MonoBehaviour），并显示每个对象的 `m_Name`；以后还可以支持按 `fileID` 跳转到对应的对象。

### 4.3 Markdown 预览

Markdown 是重点处理的文档类型，**完整支持，效果与 VS Code 一致**（D5）。预览用系统自带的 WebView2 渲染，这是 Rove 中唯一使用网页内核的地方，其余界面仍然是原生渲染。

**打开方式（D6）**

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 打开 `.md` 文件 | 以源码打开 | **默认以预览打开** | D6：Markdown 主要是用来阅读的 |
| 修改默认打开方式 | 设置 `workbench.editorAssociations`，把 `*.md` 关联到 `vscode.markdown.preview.editor` | 遵循同一个设置项；用户**没有设置**时，Rove 默认使用预览（第 13 节规则 5：Rove 的默认值不写入共用的设置文件） | D4 |
| 在预览与源码之间切换 | 编辑器标题栏中的“打开预览”按钮，或命令 | 编辑器标题栏中的“显示源码 / 显示预览”切换按钮；快捷键 `Ctrl+Shift+V`（在预览和源码之间切换；直接沿用 VS Code 1.145 已有的 `markdown.togglePreview` 命令及其默认键位） | 预览是默认状态后，需要一个对称的切换方式 |
| 在预览中想要修改内容 | — | 双击预览中的某个位置时，切换到源码并定位到对应行；或者按 `Ctrl+K V` 打开左右并排的“源码 + 预览” | 编辑是局部、低频的操作 |
| 快速打开、文件树、搜索结果中打开 `.md` | 源码 | 文件树和快速打开：打开预览；**从搜索结果、跳转、引用中打开：打开源码并定位到匹配处** | 有明确位置的跳转，必须能看到具体位置 |

**渲染**

| 场景 | VS Code | Rove | 原因 |
|---|---|---|---|
| 样式 | `markdown.css`，跟随颜色主题 | 相同（直接使用 VS Code 的 `markdown.css` 和 `highlight.css`） | 照搬 |
| 代码块高亮 | 按语言高亮 | 相同，颜色跟随当前主题 | 照搬 |
| 内嵌 HTML | 经过安全过滤后渲染 | 相同；禁止执行脚本 | 照搬 |
| Mermaid 图 | 内置支持 | 相同（打包 mermaid.js，离线可用，不联网） | D5 |
| 数学公式 | 内置支持（KaTeX） | 相同（打包 KaTeX，离线可用） | D5 |
| 本地图片 | 显示 | 相同 | 照搬 |
| 远程图片、外部资源 | 默认允许加载；可以通过预览安全设置限制 | **默认不加载**，在预览顶部提示“已阻止 N 个远程资源”，点击后可以为当前文档允许 | 立项文档：Rove 不主动发起网络请求 |
| 链接 | 相对路径的 `.md` 链接在预览中打开；外部链接用浏览器打开 | 相同 | 照搬 |

**交互**

| 场景 | VS Code | Rove |
|---|---|---|
| 滚动同步 | 编辑器与预览双向同步 | 相同 |
| 选择与复制文本、`Ctrl+F` 查找、锁定预览 | 支持 | 相同 |
| 预览中的大纲 | 资源管理器的大纲小节显示标题层级 | 相同，点击标题后在预览中滚动到对应位置 |

**性能约定**

- WebView2 **只在第一次打开 Markdown 预览时才创建**，不影响 Rove 的冷启动（< 400 ms）。
- 同一个窗口中的所有 Markdown 预览共用一个 WebView2 实例；所有预览都关闭后 N 分钟（默认 5 分钟），销毁这个实例以释放内存。
- 第一次打开预览时，WebView2 还没准备好之前，先显示一个占位状态（标题和正文的骨架），不留白。
- 已知的技术风险（弹出层被预览区域遮挡、焦点路由）需要在 M1 之前完成验证（`PLAN.md` 阶段 0.2a）。

## 5. 上下文篮子

VS Code 没有这个功能，它是 Rove 新增的（FEATURES §9，P1）。用途是：在阅读时把多段代码（可以来自多个文件）收集起来，整理成结构化的文本，复制到剪贴板，交给外部 AI 工具（Claude Code、Codex 等）。**Rove 不会把内容发送到任何地方**，只负责整理和复制。

### 5.1 加入篮子

| 入口 | 加入的内容 |
|---|---|
| 编辑器右键菜单“添加到上下文篮子”，或快捷键（命令 ID `rove.contextBasket.add`，键位在阶段 0.3 的兼容清单中确定，不能与 VS Code 的默认键位冲突） | 有选区时：选中的行区间（多光标时，每个选区各成一段）；没有选区时：光标所在的**符号**（整个方法或整个类，来自大纲） |
| 资源管理器右键菜单 | 整个文件（可以多选） |
| 大纲右键菜单 | 该符号的完整范围 |
| 速览窗口中的结果列表 | 选中的引用位置，以及它前后各 N 行（默认 3 行） |
| 搜索结果右键菜单 | 选中的匹配行（前后各 N 行），或者整个文件 |
| Markdown 预览中的选区 | 映射回源码中对应的行区间 |

加入后，活动栏的篮子图标上显示条目数量，并在状态栏临时提示“已添加到上下文篮子（共 4 段）”。**不弹出通知，也不切换视图**，以免打断阅读。

### 5.2 篮子视图（活动栏 → 上下文篮子）

| 元素 | 说明 |
|---|---|
| 顶部的“说明”输入框 | 可以选填，写给 AI 的总体说明或问题，导出时放在最前面 |
| 条目列表 | 每个条目显示：序号、文件相对路径、行号区间、所属符号（例如 `Player.Move(Vector3)`）、代码的前两行预览、备注（点击后可以直接编辑） |
| 条目操作 | 点击：在编辑器中定位并高亮该区间；拖动：调整顺序；悬停时出现的按钮：编辑备注、删除 |
| 底部的统计 | 总行数、总字符数、估算的 token 数（按字符数在本地估算，不调用任何服务）；超过 10 万字符时数字变为警告色 |
| 底部的操作按钮 | **复制为 Markdown**（主按钮）、复制为引用、清空 |

**自动处理的规则**：
- 同一文件中重叠或相邻的区间自动合并，备注也一并合并。
- 条目记录的是**位置**，不是快照：文件内容变化后，区间会跟随编辑自动平移；导出时使用文件的**当前内容**。如果文件在外部被大幅修改，导致区间无法可靠地跟随，条目会标记为“可能已过期”，点击后可以重新选择范围。文件被删除时，条目标记为“文件已删除”，导出时跳过。
- 篮子的内容**按工作区保存**，重启 Rove 后仍然存在。它保存在 Rove 自己的状态目录中，不写入项目目录。

### 5.3 导出格式

**复制为 Markdown**（默认）：

````markdown
<说明输入框中的内容（没有填写时省略这一段）>

## 1. Assets/Scripts/Player.cs:41-58 · `Player.Move(Vector3)`

<备注（没有填写时省略）>

```csharp
public void Move(Vector3 dir)
{
    ...
}
```

## 2. Assets/Config/items.json:12-30
...
````

规则：
- 路径是相对于工作区根目录的路径，用 `/` 分隔；行号从 1 开始。
- 代码块的语言标记取自当前文件的语言模式。
- 换行符统一为 LF，编码统一为 Unicode。
- 代码内部本身包含 ```` ``` ```` 时，自动加长外层的围栏。

**复制为引用**：每段一行，默认格式为 `@Assets/Scripts/Player.cs (lines 41-58)`（路径中有空格时写成 `@"…"`）。调研发现 Claude Code、Codex、dsh 都不能解析写在路径里的 `#L` 行号区间，所以行号必须写在路径后面、用空格隔开，详见 `docs/compat/REFERENCE_FORMATS.md`。格式可以通过 `rove.contextBasket.referenceTemplate` 修改（默认值 `@{path} (lines {start}-{end})`）。

**按工具预设**：你常用的是 Claude Code 桌面版、Codex 桌面版和 dsh 桌面版。如果实测发现三个工具的表现不一致，就为它们分别提供预设，在篮子视图中通过下拉框切换。每个预设的具体格式（路径写法、行号写法、粘贴后能否被识别为文件引用）**在阶段 0.3 中逐个工具实测后确定**，不凭推测；dsh 的格式需要你提供资料，或者由你协助实测。

**复制之后**：状态栏临时提示“已复制 3 段内容（约 2.1k tokens）”。是否在复制后自动清空篮子，由 `rove.contextBasket.clearAfterCopy` 控制，默认不清空。

### 5.4 不做的事情
- 不直接发送给任何 AI 服务，也不调用任何外部程序。
- 不提供导出模板编辑器（P2 再考虑可以自定义的 Markdown 模板）。
- 不支持把二进制文件或超大文件整个加入篮子；对超大文件只能加入选中的区间，单个条目上限为 1 万行。

## 6. 全局状态：通知、加载、空状态、错误

本节是全局统一的规则；前面各块中的具体场景都要遵守这些规则。措辞风格沿用 VS Code：先说发生了什么，再说可以怎么做，不带“错误：”这类前缀。

### 6.1 反馈分级

只有当前一级不够用时，才使用下一级。

| 级别 | 形式 | 适用场景 | 例子 |
|---|---|---|---|
| 1 状态栏临时消息 | 状态栏左侧的一行文字，3 秒后消失 | 操作成功的回执、不需要用户处理的提示 | “已复制 3 段内容（约 2.1k tokens）”“近似结果：语义索引未就绪” |
| 2 光标处的提示 | 在光标位置弹出的小提示，与 VS Code 的“未找到定义”提示相同 | 当前操作没有结果 | “未找到 `Move` 的引用” |
| 3 编辑器顶部的提示条 | 编辑器内容上方的一条提示，可以关闭，可以选“不再提示” | 与**当前文件**相关的背景信息 | 超大文件只读、共用设置文件、已阻止远程资源 |
| 4 通知 | 右下角的通知，与 VS Code 相同（信息 / 警告 / 错误三级） | 需要用户知道、或者需要用户操作的**全局**事件 | 索引失败、保存失败、外部修改与本地修改冲突 |
| 5 模态对话框 | 阻塞式对话框 | **只用于不立即处理就会丢失数据的情况** | 关闭有未保存修改的文件、保存时有无法编码的字符 |

**通用规则**：
- 同一原因的通知不重复弹出：再次触发时只更新已有通知中的次数。
- 照搬 VS Code 的“勿扰模式”：开启后只显示错误级别的通知。
- 正常的后台工作（索引、扫描、预读）**永远不弹通知**，只在状态栏显示进度。

### 6.2 加载与进度

**原则：先显示已有的内容，然后逐步补全；任何时候都不阻塞界面。**

| 场景 | 规则 |
|---|---|
| 启动 | 400 ms 内显示窗口，并恢复上次的布局；上次打开的标签按需加载（先加载当前可见的那个） |
| 打开文件 | 100 ms 内完成时不显示任何加载状态；超过 100 ms 时，在标签栏下方显示 VS Code 那样的细进度条；超大文件先显示首屏（§3.2） |
| 工作区扫描 | 资源管理器立即显示根目录；快速打开立即可以使用，扫描完成前在列表底部显示“正在加载文件列表…” |
| 全局搜索 | 搜索视图顶部显示进度条，结果以流的形式逐步出现；可以随时取消（照搬 VS Code） |
| 悬停、速览 | 300 ms 内没有结果时，显示“正在加载…”（照搬 VS Code）。由于查询本身是微秒级的，这种情况只在索引冷读取时出现 |
| C# 索引 | 只在状态栏显示（§2.1） |
| Markdown 预览首次打开 | 先显示骨架占位（§4.3） |
| 耗时操作 | 凡是可能超过 1 秒的操作（搜索、格式化大文件、重建索引）都必须可以取消 |

### 6.3 空状态

| 位置 | 显示内容 |
|---|---|
| 没有打开文件夹的窗口 | 欢迎页（§1.6） |
| 资源管理器（没有打开文件夹） | “尚未打开文件夹。”加“打开文件夹”按钮（照搬 VS Code） |
| 全局搜索没有结果 | “未找到结果。”加“查看排除设置”链接；如果 Rove 的默认排除规则（例如 Unity 的 `Library/`）影响了结果，额外提示“已排除 Unity 生成的目录”，并提供“包含排除的文件再搜索一次” |
| 大纲（当前文件类型不支持） | “活动编辑器无法提供大纲信息。”（照搬 VS Code 的措辞） |
| 转到定义、查找引用没有结果 | 光标处提示“未找到 `X` 的定义”或“未找到 `X` 的引用”；如果当前是近似结果，在后面加上“（语义索引构建中）” |
| 问题面板 | “未在工作区检测到问题。” |
| 上下文篮子 | “选中代码后，右键选择‘添加到上下文篮子’，或者使用快捷键。”加一张简短的示意图 |

### 6.4 错误处理

| 场景 | 处理方式 |
|---|---|
| 无法打开文件（不存在、没有权限、被占用、路径过长） | 标签仍然打开，内容区显示错误占位页：原因的一句话说明，加“重试”“在资源管理器中显示”按钮（照搬 VS Code 的“无法打开编辑器”页面） |
| 保存失败：文件被其他程序占用（例如 Unity 正在导入） | 通知：“无法保存 `Player.cs`：文件被其他程序占用。”按钮：“重试”“另存为”。自动重试一次后才弹出通知 |
| 保存失败：文件有只读属性 | 通知，按钮：“覆盖”（清除只读属性后保存）、“另存为”。**不提供“以管理员身份保存”** |
| 保存冲突：文件在磁盘上已被修改 | 照搬 VS Code：通知，按钮“比较”（P2，对比视图完成之前先隐藏）、“覆盖”“放弃本地修改” |
| 设置文件有语法错误 | 继续使用上一次有效的设置；状态栏显示警告图标；问题面板中列出错误位置 |
| 索引进程崩溃 | 按 §2.1 的“失败”状态处理；自动重试一次 |
| 本机没有 WebView2 运行时（部分 Windows 10） | Markdown 改为以源码打开；弹出一次通知，说明需要安装 WebView2 运行时，并提供微软官方下载页的链接。**Rove 不会自动下载** |
| Rove 上次意外退出 | 下次启动时恢复热退出的备份（FEATURES §6），并在状态栏提示“已恢复上次未保存的修改”。崩溃日志只保存在本地，不上传 |
