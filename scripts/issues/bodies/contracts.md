## 背景

Rove 会由多个会话在多个工作区中并行开发，接缝问题是主要风险：如果共享接口没有事先定义，各个 issue 只能各自猜测，合并时互相对不上（见 `docs/issues/README.md` §0 拆分原则）。

本 issue **先于所有核心层和界面 issue 完成**。它不实现功能，只做三件事：
1. 确定 crate 划分与依赖方向；
2. 把所有跨 issue 共享的接口写成**能编译的类型、trait 和空实现**，并写清楚每个接口的契约；
3. 建立统一的**登记机制**（命令、设置项、颜色键、界面字符串、视图），让后续 issue 只需“往里登记”，不需要各自发明做法。

必读：`docs/PROJECT_CHARTER.md`、`docs/FEATURES.md`（尤其 §12 决策 D1–D7、§13 共用设置规则）、`docs/UX_SPEC.md`、`docs/compat/*`、`docs/LANGUAGE_INTELLIGENCE.md`、`docs/M0_UI_SPIKE_REPORT.md` §7。

## 目标

### 1. crate 划分与 `docs/ARCHITECTURE.md`

在现有 workspace（`crates/rove-*`）的基础上确定最终的 crate 划分。建议如下，可以调整，但调整要在 PR 中说明理由：

| crate | 职责 | 可以依赖 gpui |
|---|---|---|
| `rove-base` | 公共基础类型：工作区内路径、位置、区间、文本编辑、取消令牌、事件订阅。**字节偏移、UTF-8 列、UTF-16 列必须是三种不同的类型**（C# 索引 v1 用 UTF-16 列，编辑器内部用 UTF-8），不能都用整数表示 | 否 |
| `rove-buffer` | 文本源与文档模型（普通文件与超大文件） | 否 |
| `rove-syntax` | 语法分析、高亮 token（带 TextMate scope）、折叠区间、文档符号、语言配置 | 否 |
| `rove-theme` | 主题模型、颜色键登记表（含默认值）、token 样式解析 | 否 |
| `rove-config` | 设置读取（与 VS Code 共用文件）、设置项登记表、变更通知 | 否 |
| `rove-commands` | 命令登记表、上下文键、`when` 表达式、键位解析 | 否 |
| `rove-i18n` | 界面字符串表与取字符串的宏 | 否 |
| `rove-workspace` | 工作区文件模型、文件事件、排除与只读规则、搜索 | 否 |
| `rove-lang-cs` | C# 导航查询（结果带精确度标记） | 否 |
| `rove-docview` | 结构树等文档视图模型 | 否 |
| `rove-ui` | 界面层：工作台、视图、编辑器 | **是** |
| `rove-app` | 程序入口、组装 | **是** |

`docs/ARCHITECTURE.md` 的内容：crate 依赖图（只允许单向依赖）、线程模型（界面线程只做布局和绘制；耗时工作放在后台执行器；结果如何回到界面线程）、各接口的归属、契约变更流程（见“完成标准”）、与性能预算相关的约定。

### 2. 共享接口（写成类型、trait 与空实现）

每个接口都必须有文档注释，写清楚：**语义、线程安全约定、性能预期（例如“必须在 O(log n) 内返回”“不得在界面线程上执行”）、错误如何表达**。下面列出必须覆盖的接口和关键要求；方法细节由本 issue 设计。

| 接口 | 所在 crate | 关键要求 | 实现方（后续 issue） |
|---|---|---|---|
| 文本源 `TextSource` | rove-buffer | 只读访问：行数（超大文件时可能是“已知行数”加进度）、按行或字节区间取文本、版本号；`Send + Sync`；不允许复制全文 | [[buffer]]、[[largefile]] |
| 文档与打开文档服务 | rove-buffer / rove-ui | 打开、按路径查找已打开的文档、定位到某个位置（打开并滚动到行列）、关闭；文档携带语言、编码、换行符、只读原因、大小级别 | [[groups]] |
| 高亮与语法结果 | rove-syntax | 按行查询 token（字节区间 + scope 列表）；增量更新后给出“哪些行变了”；结果过期时可以继续使用旧结果 | [[syntax]] |
| 折叠区间、文档符号 | rove-syntax | 统一的区间与符号树类型，供折叠、大纲、面包屑、粘性滚动、上下文篮子共用 | [[codeview-hl]]、[[outline]] |
| 语言配置 | rove-syntax | 括号、注释、自动闭合、折叠标记、单词规则、缩进规则的数据模型 | [[langcfg]] |
| 主题与颜色键登记 | rove-theme | 颜色键登记（键名 + 深色 / 浅色 / 高对比度默认值）；按 scope 解析 token 样式；主题变更通知 | [[theme]] |
| 设置读取与设置项登记 | rove-config | 强类型读取（支持语言级覆盖）；设置项登记（键名、默认值、Rove 的默认值差异）；变更通知；写入接口（保留格式） | [[settings]] |
| 命令、上下文键与键位 | rove-commands | 命令登记（VS Code 命令 ID）、执行、参数；上下文键的设置与订阅；`when` 表达式求值；按键 → 命令的解析接口 | [[keys]] |
| 界面字符串 | rove-i18n | 所有用户可见字符串通过一个宏按键取值；本 issue 只建中文表，英文表由 [[i18n]] 补齐 | 全部界面 issue |
| 工作区 | rove-workspace | 文件列表与目录树模型、文件事件流、排除与只读规则查询 | [[workspace]] |
| 反馈 | rove-ui | UX_SPEC §6.1 的五级反馈：状态栏临时消息、光标处提示、编辑器提示条、通知、模态对话框 | [[shell]] |
| 列表、树与快速输入 | rove-ui | 虚拟化列表与树、键盘导航、过滤、快速输入框的组件接口 | [[lists]] |
| 视图与贡献点 | rove-ui | 活动栏视图、侧边栏视图、面板视图、状态栏条目、编辑器标题栏按钮的登记方式 | [[shell]] |
| C# 导航查询 | rove-lang-cs | 定义、类型定义、引用、实现与派生关系、悬停、文件内符号、工作区符号、按文件取语义 token（行、UTF-8 列、长度、token 类型、修饰符）、按文件取不生效的预处理区域；结果带精确度（精确 / 近似 / 语法）；同步查询接口 | [[router]] |

### 3. 统一的登记机制

后续每个 issue 新增的东西，都必须通过这里的登记机制加入，**不允许写死**：
- 命令（VS Code 命令 ID，见 `docs/compat/KEYBINDINGS.md`）
- 设置项（见 `docs/compat/SETTINGS.md`）
- 颜色键（见 `docs/compat/THEME_COLORS.md`）
- 界面字符串
- 视图与状态栏条目

### 4. 空实现

每个接口都提供一个“最简实现”（返回空结果或固定值），保证整个 workspace 能编译、能运行最简单的测试。这些最简实现会在 [[skeleton]] 中被替换为能跑通链路的简易实现，再由各个 issue 替换为正式实现。

## 不包含

- 任何功能的正式实现。
- 界面绘制（由 [[skeleton]] 开始）。
- CI 配置（由 [[ci]] 负责；两者可以并行，`AGENTS.md` 中与架构相关的部分以本 issue 的 `ARCHITECTURE.md` 为准）。

## 验收标准

- [ ] `docs/ARCHITECTURE.md` 完成，覆盖上面列出的全部内容
- [ ] 上表中的每个接口都有类型或 trait、文档注释（语义、线程安全、性能预期、错误）以及空实现
- [ ] 每个接口都有至少一个“消费方示例测试”，演示后续 issue 应该怎样使用它
- [ ] 五类登记机制都可用，并各有一个登记示例
- [ ] 核心层 crate 的依赖树中没有 `gpui`（`cargo tree -p <crate> -i gpui` 为空）
- [ ] `cargo build --workspace`、`cargo test --workspace`、`cargo clippy --workspace -- -D warnings` 全部通过
- [ ] PR 描述中附上接口清单，以及每个接口“由哪个 issue 实现”的对照表

## 完成标准补充：契约变更流程

本 issue 合并后，接口文件进入“契约”状态：
- 后续 issue **不得在自己的 PR 里顺手修改契约**；
- 确实需要修改时，单独提一个小 PR，说明原因和对其他 issue 的影响，合并后其他会话再 rebase；
- 这条规则同时写入 `AGENTS.md`（与 [[ci]] 协调）。

## 风险与提示

- 接口设计得太细，会限制实现方；设计得太粗，又起不到约束作用。原则是：**只约束跨 issue 共享的部分，单个 issue 内部的实现细节不在契约中规定**。
- 性能约定要写进契约。例如 `TextSource` 如果设计成返回 `String`，代码视图就无法避免复制；要参考 M0 的实测数据（`docs/M0_UI_SPIKE_REPORT.md`、`docs/M0_LANG_SPIKE_REPORT.md`）。
- GPUI 的类型不能出现在核心层的接口中。界面层需要的颜色、字体等，在核心层用自己的类型表示，到 `rove-ui` 中再转换。
