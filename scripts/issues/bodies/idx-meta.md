## 背景

M0 发现：**约 30% 的跳转目标是 DLL 里的符号**（UnityEngine、BCL、第三方库），源码中根本没有定义，跳转直接落空（`M0_LANG_SPIKE_REPORT`"对设计文档的修正"第 3 条，结论是"M2 必须做"）。对 Unity 项目来说这就是日常：`transform.position`、`List<T>.Add`、`GetComponent<T>` 全是外部符号。

解决办法不是反编译，而是**由索引进程预先生成"元数据视图"**：用 C# 语法写出类型的公共与受保护成员签名，加上 XML 文档注释，当作一份只读的虚拟源文件存进索引。外部符号的"定义位置"就指向这份视图里的对应行。内容规格见 `UX_SPEC` §4.1，设计依据见 `LANGUAGE_INTELLIGENCE` §3.3 的"外部符号"一行。

本 issue 只做**生成**：填 [[idx-format]] 在 v2 中预留的那几个段。打开标签、面包屑、标签复用等界面行为是 [[meta-ui]]。

## 目标

### 1. 视图内容（`UX_SPEC` §4.1）

对被引用到的外部类型，生成一份 C# 风格的文本：

- **只有签名，没有方法体，不做反编译**。方法体写成 `;` 或省略号形式都可以，但要能通过 [[syntax]] 的 C# 语法高亮（视图是当作 C# 文件显示的）。
- 成员范围：公共与受保护成员（含字段、属性、方法、事件、构造函数、运算符、索引器、嵌套类型声明）。
- 签名用 Roslyn 的 `SymbolDisplayFormat` 渲染，保证泛型参数、约束、可空标注、默认值、`params`、`ref`/`out`/`in` 都正确。
- XML 文档注释以 `///` 的形式写在成员上方。**Unity 的 DLL 旁边通常有同名的 `.xml` 文档文件**，要去读；BCL 的文档在 .NET 参考程序集目录下。找不到文档文件时只输出签名，不报错。
- 文档注释的显示与否由 `rove.metadataView.showDocs` 控制（`SETTINGS.md` §4），但那是**界面侧的开关**：索引里始终存原始文档文本，不要在生成期按设置裁剪。

### 2. 文件头

视图开头是一个默认展开的 `#region`，内含程序集名、版本、DLL 的完整路径，照搬 Visual Studio 的写法（`UX_SPEC` §4.1 "文件头"一行）。

### 3. 成员位置

视图文本中**每个成员所在的位置**（行、UTF-8 字节列、长度）写进预留段，并与符号表建立对应关系：外部符号的定义位置 = 视图序号 + 视图内位置。这样 [[router]] 查"定义"时，外部符号与源码符号走的是同一条路径，只是落点在视图里。

嵌套类型按 `UX_SPEC` §4.1 的要求处理：生成**外层类型**的视图，嵌套类型在其中有自己的位置。

### 4. 只生成被引用到的类型，并去重

体积是硬约束。规则：

- 只为索引过程中**实际被引用到**的外部类型生成视图（BCL 有几万个类型，全量生成不可接受）；
- 多个项目引用同一个 DLL 时只生成一次（按"程序集标识 + 类型的文档注释 ID"去重）；
- 同一个类型在不同版本的程序集中出现时，按程序集版本区分，不要合并。

### 5. 报告

在 `--report` 中新增：生成的视图数量、总文本字节数、带文档注释的比例、以及**外部符号跳转落空率**（有多少外部符号的引用找不到对应的定义位置）。

## 不包含

- 元数据视图的界面：标签标题 `Transform [元数据]`、锁形图标、面包屑、标签复用、"未找到元数据"的临时提示（全部是 [[meta-ui]]）。
- 在元数据视图里继续跳转、以及在视图中查找引用（[[meta-ui]] 与 [[router]]；本 issue 只保证索引里有它们需要的数据）。
- 反编译方法体。明确不做，`UX_SPEC` §4.1 已经定了。
- 段的布局定义（[[idx-format]]）。
- 增量更新时元数据视图的重建（[[idx-incr]]；DLL 不变时视图不需要重建，这一点要在 PR 中写清楚）。

## 验收标准

- [ ] 抽查三个符号，都能跳到视图中的正确位置并带文档注释：`UnityEngine.Transform.position`、`System.Collections.Generic.List<T>.Add`、以及任选一个第三方 DLL 中的符号
- [ ] 视图文本能被 C# 语法解析器正常解析（用 Roslyn 在生成侧自检：解析后无语法错误）
- [ ] 文件头 `#region` 含程序集名、版本、DLL 完整路径
- [ ] 一个带嵌套类型的外部类型：视图中有嵌套类型的声明，且跳转定位到它
- [ ] 一个泛型类型（如 `Dictionary<TKey, TValue>`）：泛型参数与约束渲染正确
- [ ] 去重有测试：大型项目中同一个 `UnityEngine.CoreModule` 被几十个项目引用，视图只有一份
- [ ] **大型项目的索引体积增加 < 30 MB**（在 [[idx-format]] 的 v2 基线上测，给出前后数字；总体积仍需 < 200 MB）
- [ ] **外部符号跳转落空率从约 30% 降到接近 0**，报告新的数字与剩余落空的原因
- [ ] 全量索引耗时的增加有数字，且大型项目仍然满足 [[idx-perf]] 的 < 90 s / < 3 GB
- [ ] 缺少 `.xml` 文档文件、DLL 被占用、DLL 版本冲突三种情况下不中断索引，记录警告

## 风险与提示

- **体积最容易失控的地方是"被引用到"的判定范围**。如果把"引用了 `List<T>.Add`"理解成"要生成整个 `System.Collections.Generic`"，30 MB 立刻爆掉。建议按类型粒度生成（引用到类型的任一成员就生成该类型的完整视图），并在报告里打印 Top 20 最大的视图，看看有没有意外被拉进来的庞然大物。
- 签名渲染不要自己拼字符串。`SymbolDisplayFormat` 能覆盖绝大部分情况，自己拼一定会在泛型约束、可空引用类型、`ref struct` 上出错。
- XML 文档注释里有 `<see cref="..."/>`、`<paramref/>` 这类标签。首版可以原样保留（视图里就是 `///` 注释，高亮能看），但要在 PR 中记录这个决定，[[meta-ui]] 可能需要进一步处理。
- **索引进程的文件按 [[idx-format]] → [[idx-perf]] → [[idx-meta]] → [[idx-incr]] 的顺序串行修改**（依赖图已保证这个顺序：[[idx-incr]] 依赖 [[idx-meta]]），因为它们都要改 `tools/rove-indexer-cs/Program.cs`。
- 索引进程**不得联网**下载文档或符号包。找不到 `.xml` 就没有文档，不要去 nuget.org 或 Microsoft 的符号服务器取。
