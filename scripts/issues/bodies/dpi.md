## 背景

立项文档 §7 把「高 DPI 与多显示器不同缩放比」列为 Windows 专项风险，M0 **没有消除这个风险**：`M0_UI_SPIKE_REPORT.md` §4.6 只用 `GetProcessDpiAwareness` 确认了两个原型进程都是 `PROCESS_PER_MONITOR_DPI_AWARE`，**没有在 125% / 150% / 200% 或多显示器混合缩放下实际跑过**，也没验证跨显示器拖动时的重排（§8 第 1 条「未验证事项」）。

这是一个**验证 + 修复**型 issue：先按矩阵跑一遍，把问题找出来，再做小范围修复。它不新增功能，所以不引入新的命令、设置项或颜色键；万一确实需要（例如一个 `rove.*` 开关），也必须通过 [[contracts]] 的登记机制加入，不得写死。

## 目标

### 1. 缩放比例矩阵

在 100%、125%、150%、200% 四种系统缩放下逐项检查（每一项都附截图）：

| 检查项 | 判据 |
|---|---|
| 文字清晰度 | DirectWrite 次像素定位与 gamma 正常，没有发虚或重影；中文与 emoji 的字体回退正常 |
| 命中测试 | 点击任意字符定位到正确的行列，CJK 全角、Tab、emoji 混排时误差 ≤ 1 个字符 |
| 插入符 | 位置与宽度正确，不随缩放比例变成半像素虚线 |
| 滚动条 | 轨道与滑块的尺寸、拖动与点击跳转的命中区正确 |
| 行号栏、缩进参考线、分隔线 | 1 物理像素的线条不消失、不变成 2 px |
| 浮层 | 快速打开与命令面板、菜单、通知、编辑器提示条、面包屑选择器、悬停卡片的定位与尺寸正确，不越界、不被裁切 |
| 图标 | codicons 字体在各缩放下不糊 |
| Markdown 预览 | WebView2 的缩放与宿主一致（与 [[markdown]] / [[webview]] 的方案对齐），不出现两套缩放叠加 |

### 2. 多显示器与跨屏拖动

- 两块不同缩放比的显示器（例如 100% + 150%）：窗口在任一屏上都正确布局。
- 把窗口从一块拖到另一块时：收到缩放变更事件后重新布局、**清空整形缓存**（M0 Route B 的做法，Route A 下必须验证 GPUI 是否已经做了）、滚动位置与选区保持不变、没有闪烁或一帧错位。
- 窗口横跨两块显示器各一半时的表现。
- 窗口在副屏上时打开浮层与 Markdown 预览。

### 3. 与字体缩放叠加

`Ctrl+=` / `Ctrl+-` / `Ctrl+0`（`editor.fontZoom*`）、`editor.fontSize` 与 `window.zoomLevel` 和系统缩放叠加时，行高、命中测试、滚动条仍然正确。

### 4. 修复

- 修复位置优先在 `rove-ui`（主要是 [[codeview]] 的 Element 与整形缓存）；确实是 GPUI 的问题时，通过 [[gpui]] 建立的 vendor 补丁机制修改 `vendor/gpui/`，并把每个补丁记录进 `vendor/gpui/ROVE_PATCHES.md`（不改动 [[gpui]] 定下的 vendor 目录结构与打补丁流程）。
- 修不了的问题写入 `ROVE_PATCHES.md` 的待办，并在 PR 中说明影响范围与规避方式。

### 5. 回归保护

在 GPUI 的测试环境中加一个缩放参数化测试：在 1.0 / 1.25 / 1.5 / 2.0 下断言代码视图的布局尺寸与“像素坐标 → 行列”的换算结果（含 CJK 与 Tab 的样例），以及一次缩放变更事件后缓存确实被清空。截图类检查仍然人工执行，清单写进 PR 描述。

## 不包含

- 任何新功能与界面重构；大范围重写 [[codeview]] 的渲染路径。
- 字体回退与 emoji 渲染本身的实现（[[codeview]]），IME 候选框位置（[[gpui]]）。
- 多显示器下的窗口位置记忆与布局持久化（[[shell]]）。
- macOS 的 DPI 行为（首发不支持，立项文档 §3）。
- 修改 [[contracts]] 的接口：需要改时走契约变更流程，单独提小 PR。

## 风险与提示

- “浮层”与“Markdown 预览缩放”两项需要 [[shell]]、[[quickopen]]、[[markdown]]，已列为前置依赖，所以本 issue 排在 M1 界面基本合并之后、[[integ-m1]] 之前。
- 需要能切换显示缩放的环境。只有一块显示器时，可以在系统设置里切换缩放比例覆盖第 1 节，但第 2 节的混合 DPI 必须用两块显示器，不能用模拟代替（这正是 M0 悬空的那一项）。
- 整形缓存的键里如果没有包含缩放比例，跨屏拖动后会复用错误的字形尺寸——这是最可能的一类缺陷，优先验证。
