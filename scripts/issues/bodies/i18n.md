## 背景

`FEATURES.md` §7 把界面语言判定为改造、P1：**内置中文和英文，不使用语言包扩展**。基础设施已经在 [[contracts]] 中建好了——`rove-i18n` 里有字符串表和取字符串的宏，所有界面 issue 的可见文字都已经按键取值，[[contracts]] 也写明「本 issue 只建中文表，英文表由 [[i18n]] 补齐」。[[shell]] 同样把「英文界面与语言切换」留给了本 issue。

所以本 issue 不新建机制，只做三件事：**补齐英文表**、**实现语言切换**、**用工具保证两份表不漂移**。

有一个必须先定的问题：VS Code 的界面语言存在 `%APPDATA%\Code\User\argv.json` 的 `locale` 里（命令是 `workbench.action.configureLocale`，`KEYBINDINGS.md` §7 附录「P0 · 窗口与设置」中列为需要实现、无默认键位），而 Rove 共用的是 `settings.json`，不是 `argv.json`。`SETTINGS.md` §4 现在也没有对应的 `rove.*` 项。本 issue 的决定见「目标 2」。

必读：`FEATURES.md` §7（界面语言一行）、§13（共用设置的 7 条规则）；`UX_SPEC.md` §0.1（没写到的一律与 VS Code 一致）、§6.1–§6.4（各级反馈的措辞风格）；`docs/compat/KEYBINDINGS.md` §7 附录（`workbench.action.configureLocale`）；`docs/compat/SETTINGS.md` §4；`docs/issues/README.md` §0 第 4 条（界面字符串必须走登记机制）。

## 目标

### 1. 英文字符串表

- 为中文表中的**每一个键**补一条英文文案，两份表的键集合完全一致。
- **移植自 VS Code 的界面，英文文案直接取 VS Code 的英文原文**（`FEATURES.md` §11：界面文案属于可复用资产，MIT，在 `THIRD_PARTY_NOTICES.md` 注明），不要把中文再翻译回英文——用户从 VS Code 迁过来时看到的应该是同一句话。Rove 特有的界面（超大文件提示条、索引状态、元数据视图、结构树、上下文篮子）才需要自己写英文，风格按 `UX_SPEC.md` §6：先说发生了什么，再说可以怎么做，不带「Error:」这类前缀。
- 带占位符的文案（`{count}`、`{path}`）在两份表中占位符的**名字与个数必须一致**；语序不同没关系，但不允许一份有两个占位符、另一份只有一个。
- 不翻译的东西：命令 ID、设置键名、颜色键名、TextMate scope、主题名、文件路径、编码名（`GBK`、`UTF-8`）。

### 2. 语言切换（`workbench.action.configureLocale`）

- 新增 Rove 专有设置 **`rove.locale`**（取值 `"auto"` / `"zh-cn"` / `"en"`，默认 `"auto"`）。它是 `SETTINGS.md` §4 之外的新增项，按 [[settings]] 的约定**改 `scripts/compat/gen_compat_docs.py` 后重新生成文档**，不手改 `SETTINGS.md`。
- 生效顺序：`rove.locale` 显式设置 → 共用用户目录下 `argv.json` 的 `locale`（**只读**，让在 VS Code 里设过显示语言的用户零成本迁移；文件不存在或无法解析时跳过，不创建、不写入）→ 系统界面语言（`zh-*` 用中文，其余用英文）。
- 命令 `workbench.action.configureLocale`（沿用 VS Code 的 ID，无默认键位）打开一个快速选择框：`中文（简体）` / `English` / `跟随系统`。选择后通过 [[settings]] 的**保留格式写入**把 `rove.locale` 写进共用 `settings.json`。
- **切换后立即生效**：字符串表是运行时查表，界面重新渲染即可。确有做不到的地方（例如已登记命令的标题缓存），改为按 `UX_SPEC.md` §6.1 第 4 级通知提示需要重启，并在 PR 中逐条列出这些地方。
- 齿轮菜单与命令面板中的入口由 [[welcome]] / [[shell]] 的菜单登记机制追加一项，不改它们的其他代码。

### 3. 完整性检查工具

- 新增 `cargo xtask i18n-check`：检查**缺键**（中文有、英文没有，或反之）、**占位符不一致**、**未使用的键**（表里有、代码里没人取）、**硬编码字面量**（`rove-ui` / `rove-app` 中出现的中文字符串字面量）。
- 前三项中任意一项不通过就**让 CI 失败**（与 [[ci]] 协调，加入它的检查清单与 `AGENTS.md` 的完成标准：「新增界面字符串必须同时登记中英两份」）。
- 未使用的键默认只告警（功能还没接上时会误报），但要能用 `--strict` 打开。

### 4. 本地化细节

- 数字、文件大小、时间的格式按 VS Code 的做法处理（文件大小 `1.2 GB`、百分比 `45%`），不引入完整的 ICU。
- 中文文案不做复数，英文文案按 VS Code 的写法处理单复数（`1 file` / `2 files`），需要时在键里分出 `_one` / `_other`。
- 字体回退已由 [[dpi]] / [[shell]] 处理，本 issue 只保证英文界面下不出现中文字形被强制等宽的问题（截图核对）。

### 5. 登记与替换

新增命令、设置项、界面字符串全部通过 [[contracts]] 的登记机制加入。[[skeleton]] 中没有本 issue 对应的 `SKELETON(...)` 标记，只在 `docs/ARCHITECTURE.md` 中新增自己的一行。不得在本 PR 中修改 [[contracts]] 的字符串表接口（需要扩展（例如加复数形式）时走契约变更流程单独提小 PR）。

## 不包含

- 中文、英文以外的语言；语言包扩展（`FEATURES.md` §7 明确不做）；从网络下载语言包。
- RTL 布局、输入法与键盘布局（[[gpui]]、[[edit-ui]]）。
- 各 issue 自己的字符串登记：本 issue 合并前已有的键由本 issue 补英文，**之后新增的键由新增它的 issue 同时登记中英两份**（规则写进 `AGENTS.md`，与 [[ci]] 协调）。
- 命令 ID 与设置键名的本地化（必须与 VS Code 一致，D4）。
- 文档（`docs/*.md`）的翻译。

## 风险与提示

- **最大的工作量是逐条核对英文原文，不是翻译**。建议写一个一次性脚本，从 VS Code 源码的 `nls` 字符串里按中文文案反查英文原文，生成初稿再人工核对；脚本和它的输出都提交，并注明 VS Code 版本（当前兼容清单基于 1.145.2）。
- 本 issue 之后，新增字符串的纪律靠 CI 守。如果 `i18n-check` 只是告警，半个月后英文表就会缺一半——所以缺键必须是**硬失败**。
- `argv.json` 只读这一条很容易写成「顺手也写进去」。绝对不要写：那是 VS Code 的启动参数文件，写坏了会导致 VS Code 起不来，而 §13 规则 3 只授权写 `settings.json`。
- 切换语言「立即生效」在界面里可能有残留（已经创建的通知、已经打开的快速选择框）。不要为此把整个工作台重建一遍，照搬 VS Code 的做法（提示重启）比做一个半吊子的热切换更可靠——哪条路都行，但要在 PR 里说清楚选了哪条。
- 英文界面是给同事和未来的开源用户看的第一印象。遇到中文表里本来就含糊的文案，**修正中文**比硬翻一遍更有价值（改中文文案属于本 issue 范围，但要在 PR 中列出改动）。
