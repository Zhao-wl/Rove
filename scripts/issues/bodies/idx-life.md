## 背景

索引本身算得再准，用户感知到的是"打开项目后多久能用、出问题时看不看得懂"。M0 在这两件事上都暴露了问题：

- **冷缓存 + 机械硬盘**：索引放在 D 盘（ST2000DM001，机械硬盘）且不在系统文件缓存中时，打开索引要 **3.4 s**，前 200 次定义跳转 p99 **166 ms**、最慢 **2.8 s**（`M0_LANG_SPIKE_REPORT` §2 的警示块）。根源是 mmap 缺页变成了 HDD 随机读。该报告据此提出三条设计要求：索引缓存默认放 `%LOCALAPPDATA%\Rove`、打开项目时后台**顺序预读**整个索引文件、路径表改二分查找（第三条由 [[idx-format]] 完成）。
- 索引是后台进程，会失败、会崩溃、会版本不匹配，用户需要一个能看状态、能重建、能看日志的入口。

本 issue 把这两件事一起做完：`crates/rove-lang-cs` 侧的索引生命周期管理，以及 `UX_SPEC` §2.1 规定的状态栏条目、详情、日志和失败通知。状态条目往 [[shell]] 的状态栏容器与反馈接口上登记；文件事件来自 [[workspace]]；索引头部的版本与配置哈希来自 [[idx-format]]。

## 目标

### 1. 缓存目录

默认 `%LOCALAPPDATA%\Rove\index\<项目路径哈希>\`，可由 `rove.index.cacheDir` 覆盖（`SETTINGS.md` §4，默认 `""` 表示用默认目录）。`rove.index.enabled` 为 `false` 时完全不启动索引，C# 导航停留在 L0/L1，状态栏按"未安装语义组件"一行的样式提示（文案区分"已禁用"）。两个设置项都通过 [[contracts]] 的设置读取接口取值，不要自己读文件。

### 2. 有效性检查

打开项目时校验缓存中的索引：magic 与**格式版本**、**生成它的索引进程版本**、**项目配置哈希**（三项都来自 [[idx-format]] 定义的头部），再加上**抽样文件哈希**（随机抽 N 个文件比对内容哈希，命中率低于阈值就判定失效）。任一项不过就全量重建。

### 3. 打开时的后台顺序预读

索引有效时立即可用，同时**在后台顺序读一遍整个索引文件**把它拉进系统缓存（顺序读对 HDD 友好得多）。预读期间查询照常走 L2，只是可能慢；L1（[[l1]]）在预读完成前兜底。预读要可取消（用户关项目时立刻停），不能占满 I/O 影响前台。

**必须报告 HDD 与 SSD 上的预读耗时**——M0 只测了 HDD 的冷读取，SSD/NVMe 的冷缓存数据"尚未测量，M2 补测"，这个补测由本 issue 完成。

### 4. 原子替换

重建完成后写临时文件再重命名替换，替换瞬间不能让正在查询的会话读到半截文件（旧的 mmap 继续有效到切换完成）。重建期间**旧索引仍然可以查询**。

### 5. 拉起与监控索引进程

- 找到组件位置：[[idx-pack]] 合并前先用开发路径（`tools/rove-indexer-cs/bin/...`），合并后改为它定义的安装位置；这段查找逻辑要收在一个函数里，方便届时替换。
- 传参、读取进度上报、把日志写到缓存目录下的日志文件。
- **崩溃或非零退出：重试一次；仍然失败就降级到 L1/L0**，记录日志并按下面第 8 条弹一次通知。Rove 主进程绝不能因为索引进程的问题而崩溃或卡住。
- [[idx-incr]] 合并后，常驻进程的启停也归这里（空闲退出由进程自己决定，Rove 负责在需要时重新拉起）。

### 6. 文件变化

订阅 [[workspace]] 的文件事件流。[[idx-incr]] 合并前：把受影响的文件标记为"过期"（[[router]] 据此把这些文件的结果降级为近似）；合并后：改为把变化转发给常驻索引进程。两种路径的切换点要在代码里写清楚。

### 7. 缓存淘汰

只保留最近 N 个项目的索引，并设总容量上限（两者都可配，默认值在 PR 中给出依据）。淘汰时不能删掉当前打开项目的索引。

### 8. 状态界面（`UX_SPEC` §2.1）

索引在后台静默进行，**正常情况下不弹任何通知**，只在状态栏左侧显示一个条目（通过 [[shell]] 的状态栏登记机制）。五种状态照 §2.1 的表实现：

| 状态 | 状态栏 | 悬停 | 点击 |
|---|---|---|---|
| 未安装语义组件 | `$(info) C# 基础导航` | 跳转和引用是近似结果 | 打开说明页面 |
| 首次构建中 | `$(sync~spin) C# 索引 37%` | 已处理 / 总数、预计剩余时间 | 索引详情 |
| 就绪 | `$(check) C#` | 上次构建时间、文件数、符号数、缓存位置和大小 | 索引详情 |
| 增量更新中 | `$(sync~spin) C#`（无百分比） | 正在更新 N 个文件 | 索引详情 |
| 失败 | `$(error) C# 索引失败` | 失败原因的一句话摘要 | 错误详情、日志、"重试" |

另外：

- **工作区里没有 C# 代码时整个条目不显示**；
- 失败时**只弹一次通知**（含"查看详情"和"重试"），同一个原因不重复弹——用 [[shell]] 的反馈系统，由它负责同因去重；
- 没找到 `.csproj` 而是按 `.asmdef` 推断项目结构时，悬停提示中加一句："未找到项目文件，正在使用推断的项目结构。在 Unity 中执行 Assets → Open C# Project 可以生成项目文件。"（M0 实测 csproj 过期是常态：中型项目有 242 个新文件不在任何 csproj 中）
- 命令 `rove.index.rebuild`、`rove.index.showDetails`、`rove.index.openLog`（`KEYBINDINGS.md` §5，均为 P0，无默认键位）通过 [[contracts]] 的命令登记机制注册；所有用户可见文案通过界面字符串表登记。

## 不包含

- 索引格式与头部字段（[[idx-format]]）、索引进程内部的性能与增量实现（[[idx-perf]]、[[idx-incr]]）。
- 组件打包、安装位置的最终确定、版本握手（[[idx-pack]]）。
- 查询路由、位置映射、精确度判定（[[router]]）；本 issue 只对外报告"索引是否就绪、哪些文件已过期"。
- L1 索引的构建与持久化（[[l1]]），但两者共用缓存目录，目录布局在本 issue 中定义。
- 导航交互与近似结果的提示（[[nav-ui]]）。

## 验收标准

- [ ] 第二次打开项目时，缓存中的索引通过有效性检查并立即可用；**预读耗时在 HDD 与 SSD 上各有一组数据**（含"预读完成前的跳转 p99"对比 M0 的 166 ms）
- [ ] 格式版本、索引进程版本、项目配置哈希、抽样文件哈希，四类失效各有一个自动重建的测试
- [ ] 重建期间旧索引仍可查询；重建完成后原子替换，查询不中断、不读到半截文件
- [ ] 索引进程缺失、启动失败、崩溃、返回非零码：Rove 不崩溃，重试一次后降级到 L1/L0，日志中有可定位的记录
- [ ] 五种状态在界面上各有一个集成测试（含悬停内容与点击行为）；工作区无 C# 代码时条目不显示
- [ ] 失败通知同一原因只弹一次；连续失败不刷屏
- [ ] 按 `.asmdef` 推断项目结构时，悬停提示包含 §2.1 规定的那句话
- [ ] `rove.index.rebuild` / `showDetails` / `openLog` 三个命令已通过登记机制注册，命令面板中可见并可执行
- [ ] `rove.index.enabled = false` 时不启动任何索引进程、不创建缓存目录；`rove.index.cacheDir` 指向自定义目录时生效（含路径不存在、无写权限的处理）
- [ ] 缓存淘汰：超过项目数或容量上限时淘汰最旧的，不会删除当前项目的索引
- [ ] 新增集成测试覆盖"打开项目 → 检查缓存 → 预读 → 就绪 → 收到文件变更 → 标记过期"；[[skeleton]] 的端到端测试继续通过
- [ ] `cargo tree -p rove-lang-cs -i gpui` 为空（状态栏条目的界面部分放在 `rove-ui`）

## 风险与提示

- **预读很容易帮倒忙**。在 HDD 上和前台查询抢 I/O，会让"打开后的头几秒"比不预读还慢。建议顺序读 + 限速 + 可取消，并实测对比"不预读 / 预读 / 限速预读"三种策略，用数据决定默认行为。
- 有效性检查的"抽样文件哈希"要权衡：抽得太少会用上过期索引（跳转到错误的行），抽得太多就把打开时间搭进去。先定一个规则（例如抽 200 个文件或 2%，取大者），把规则和理由写进 PR。
- 状态栏条目是本 issue 唯一的界面产出，但它依赖 [[shell]] 的状态栏与反馈登记机制。**不要自己画状态栏，也不要绕过反馈接口直接弹通知**，否则同因去重和勿扰模式都会失效。
- 日志文件会无限增长（常驻模式下尤其）。要有轮转或大小上限，`openLog` 打开的是最新的那一份。
- 这个 issue 横跨"进程管理"和"界面状态"，很容易写成一团互相回调的意大利面。建议把索引状态建模成一个显式的状态机（未安装 / 构建中 / 就绪 / 增量中 / 失败 / 已禁用），界面只订阅状态变化，所有状态迁移集中在一处。
