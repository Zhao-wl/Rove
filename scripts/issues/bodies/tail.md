## 背景

`FEATURES.md` §6 把「跟随文件末尾（类似 `tail -f`）」列为 Rove 新增、P1，用途写得很具体：查看 Unity 的 `Editor.log`。`UX_SPEC.md` §3.2 最后一行给出了完整交互：**文件增长时自动滚动到最后一行；用户向上滚动时自动暂停跟随，状态栏显示「已暂停跟随」，点击恢复**。§3.3 第二行给出了另一半：压缩成一行的 JSON，在行尾截断标记旁边提供「**格式化后查看**」，在新标签中打开格式化后的**只读副本**，原文件不动。

这两件事都挂在同一处基础设施上：[[largefile]] 的**追加内容增量索引**（文件只在末尾追加时只更新索引尾部，不重建）和 [[largefile-ui]] 的行索引进度与截断标记。[[largefile-ui]] 已经明确把这两个命令留给本 issue，并且「不预留界面元素」。

必读：`UX_SPEC.md` §3.1（文件大小分级）、§3.2（超大文件模式的交互，尤其最后两行）、§3.3（超长行与压缩 JSON）、§6.1（反馈分级）、§6.2（耗时操作必须可取消）；`FEATURES.md` §6；`docs/compat/KEYBINDINGS.md` §5（`rove.editor.followTail`、`rove.editor.viewFormatted`，均无默认键位）；`docs/compat/SETTINGS.md` §4（`rove.largeFile.threshold`）。

## 目标

### 1. 跟随文件末尾（`rove.editor.followTail`）

- 命令是一个**按编辑器生效的开关**（Rove 专有命令，无默认键位，出现在命令面板与编辑器标题栏菜单中）。对任意文本文件都可用——`Editor.log` 常常只有几 MB，不应该要求先达到超大文件级别。
- 开启后：文件增长时自动滚动到最后一行。增长的感知来自 [[workspace]] 的文件事件 + [[largefile]] 的**追加增量索引**，只更新索引尾部，**不重建行索引、不重新读整个文件**。
- 文件被截断或整体重写（日志轮转）时，退回「重新映射并保持在末尾」，不残留旧内容；这条路径要有测试。
- 滚动与绘制全部复用 [[codeview]]，本 issue 只决定「滚到哪里」，不碰滚动模型。

### 2. 暂停与恢复

- **用户向上滚动即暂停**（滚轮、拖动滚动条、`page up`、`ctrl+home` 都算），暂停后文件继续增长但视口不动。
- 状态栏通过 [[shell]] 的状态栏条目登记机制注册一个条目，`when` 限定为「当前编辑器开启了跟随」：跟随中显示「跟随末尾」，暂停后显示「**已暂停跟随**」，点击恢复跟随并立即滚到末尾。`UX_SPEC.md` §3.2 只规定了暂停态的文案，「跟随中」那一态的文案由本 issue 确定并在 PR 中记录。
- 用户自己滚回最后一行时也恢复跟随（`tail -f` 类工具的通行做法；同样在 PR 中记录这个决定）。
- 关闭标签、切换文件时跟随状态随该编辑器一起结束，不是全局开关。

### 3. 格式化后查看（`rove.editor.viewFormatted`）

- 入口有两处：命令面板，以及 [[largefile-ui]] 的行尾截断标记旁边（标记本身属于 [[largefile-ui]]，本 issue 只往它的扩展点登记一个动作；该扩展点不存在时走契约变更流程单独提小 PR，**不在本 PR 中改 [[largefile-ui]] 的代码**）。
- 行为：在**新标签**中打开格式化后的副本，标签标题形如 `items.json（格式化后）`，内容**只读**（只读来源与 `UX_SPEC.md` §3.4 一致，显示锁形图标），**原文件不做任何改动**（验收时做字节级比对）。副本是内存文档，通过 [[groups]] 的打开文档服务创建。
- **格式化本身不在本 issue 实现**：JSON / XML 的格式化与压缩由 [[structure]] 负责（`FEATURES.md` §4「格式化」一行、`UX_SPEC.md` §4.2）。本 issue 调用它，并在 `docs/ARCHITECTURE.md` 中记下这条依赖。（[[structure]] 已列为前置依赖。）
- 大小保护：整个文件只有一行的压缩 JSON 可能有几百 MB，格式化后体积翻倍。超过一个阈值（以 `rove.largeFile.threshold` 为参考，具体取值在 PR 中说明）时拒绝并给出一句话原因；允许执行时按 §6.2 显示进度并**可以取消**。
- 非 JSON / XML 的文件上这个命令不可用（命令面板中按 `when` 隐藏）。

### 4. 登记与替换

两条命令、状态栏条目、界面字符串、颜色键的使用全部通过 [[contracts]] 与 [[shell]] 的登记机制加入，不得写死。[[skeleton]] 中没有本 issue 对应的 `SKELETON(...)` 标记，只在 `docs/ARCHITECTURE.md` 中新增自己的一行。不得在本 PR 中修改 [[contracts]] 的接口。GPUI 类型只出现在 `rove-ui` / `rove-app`。

## 不包含

- 行索引与进度、只读提示条、`rove.editor.openLongLine`、流式查找、截断标记本身（全部属于 [[largefile-ui]]）；内存映射与追加增量索引（[[largefile]]）。
- **JSON / XML 的格式化与压缩算法**、`rove.json.minify`、结构树、问题面板（[[structure]]）。
- 软换行（[[wrap]]）；只读副本里如果需要软换行，沿用 [[largefile-ui]] 已有的临时实现。
- 日志文件的语法高亮 / 着色（没有 `.log` 语法，`FEATURES.md` §9 的语言清单里也没有）。
- 外部修改的通用重载策略（[[largefile]] / [[save]]）；本 issue 只处理「末尾追加」与「被截断」两种情况下的跟随行为。
- 「跟随」状态的持久化（重开文件后默认不跟随）。

## 验收标准

- [ ] 用脚本以每秒 1000 行持续追加一个 `Editor.log` 级别的日志文件（≥ 200 MB），开启跟随后视口稳定停在最后一行，**连续跟随时每帧 CPU < 1 ms**（附测量数据，口径同 `PROJECT_CHARTER.md` §6）
- [ ] 跟随期间只触发追加增量索引，不出现整文件重新索引（断言索引调用次数 / 耗时）
- [ ] 向上滚动后**立即暂停**（下一帧内不再自动滚动），状态栏显示「已暂停跟随」；点击该条目恢复跟随并跳到末尾
- [ ] 手工滚回最后一行后自动恢复跟随
- [ ] 日志被轮转（文件被截断 / 替换）后跟随仍然正确，不显示旧内容、不崩溃
- [ ] 关闭标签后跟随结束；另一个标签的跟随状态互不影响
- [ ] 超大文件（≥ 64 MB）上跟随与 `UX_SPEC.md` §3.2 的只读提示条、`行索引 45%` 共存，三者文案不互相覆盖
- [ ] 「格式化后查看」：在一个压缩成一行的真实 JSON（Unity `.asset` 或清单）上执行后，新标签为**只读**、标题带「（格式化后）」、内容已缩进；**原文件字节级未改动**
- [ ] 超过阈值的压缩 JSON 上拒绝格式化并给出一句话原因；允许执行时进度可见且可取消
- [ ] 非 JSON / XML 文件上 `rove.editor.viewFormatted` 在命令面板中不出现
- [ ] 两条命令都通过登记机制注册，`keybindings.json` 中给它们自定义键位后生效
- [ ] [[skeleton]] 的端到端测试仍然通过；新增「追加 → 自动滚动 → 上滚暂停 → 点击恢复」的集成测试
- [ ] `docs/ARCHITECTURE.md` 的对照表已更新；本 PR 没有修改 [[contracts]] 的接口

## 风险与提示

- **「自动滚动」和「用户滚动」必须能区分开**，否则跟随本身触发的滚动会被当成用户滚动而立即暂停。在滚动事件里带上来源标记，不要用「位置是否变化」来猜。
- 文件事件会成风暴：日志每秒追加上千行时，不要每个事件都滚动一次。按帧合并（每帧最多滚一次到当前末尾），否则帧预算一定超。
- Windows 上被其他进程持续写入的文件是**共享读打开**的，映射长度不会自动变。要么定期查询文件大小，要么在事件到来时重新查询，不能假设 mmap 会跟着变长。
- 「格式化后查看」最容易做成「把格式化结果写回一个临时文件」。不要落盘：只读内存文档就够了，落盘会带来清理、权限和误以为改了原文件的问题。
- 这个 issue 难度评为 1，但它依赖两处别人的基础设施（追加增量索引、截断标记扩展点）。**开工第一件事是确认这两处都已可用**，不可用就先报出来，不要自己在本 PR 里补。
